# Дисконтированная доходность

## Зачем это нужно

В обучении с подкреплением (*reinforcement learning*, RL) агент получает
награды (*rewards*) не только сейчас, но и на следующих шагах эпизода
(*episode*). Чтобы сравнить два решения, недостаточно смотреть лишь на
ближайшую награду: нужно учесть всю последовательность будущих наград.

Дисконтированная доходность (*discounted return*) складывает эти награды так,
что ближайшие влияют сильнее, а далёкие — слабее. Коэффициент
дисконтирования задаёт, насколько агент ценит будущее. Эта величина лежит в
основе функции ценности и уравнений Беллмана.

## Обозначения

**Таблица 1. Обозначения.**

| Символ | Значение | Роль |
|---|---|---|
| $\enfTgt{G}_t$ | дисконтированная доходность с момента $t$ | `target` |
| $\enfTgt{R}_{t+1}$ | награда, полученная при переходе с шага $t$ на шаг $t+1$ | `target` |
| $\enfPar{\gamma} \in [0, 1]$ | коэффициент дисконтирования (*discount factor*) | `parameter` |
| $\enfOp{\sum}$ | суммирование вкладов наград | `operator` |
| $T$ | число наград в эпизоде | нейтральная константа |
| $t$, $k$ | номер текущего шага и счётчик слагаемых | нейтральные индексы |

В формулах цветом выделены только те роли, которые важны для текущего
разбора: $\enfTgt{G}$ — искомая доходность, $\enfPar{\gamma}$ —
настраиваемый коэффициент, а $\enfOp{\sum}$ — операция, собирающая вклады.
Награда $R$ остаётся нейтральной в самих формулах, но её роль цели указана в
таблице; это сохраняет формулы читаемыми и не превышает лимит раскраски.

## Определение доходности

> [!intuition] Сначала — ближайшая награда
> Если агент получает награду сейчас, её вклад в доходность равен самой
> награде. Награда через один шаг умножается на $\enfPar{\gamma}$, через два
> шага — на $\enfPar{\gamma}^2$. При $\enfPar{\gamma} = 0$ агент учитывает
> только ближайшую награду; при $\enfPar{\gamma} = 1$ в конечном эпизоде все
> награды имеют одинаковый вес.

> [!definition] Определение 1. Дисконтированная доходность
> Для эпизода с $T$ наградами доходностью с момента $t$ называется величина
>
> $$
> \enfTgt{G}_t = \enfOp{\sum}_{k=0}^{T-t-1}
> \enfPar{\gamma}^{k} R_{t+k+1},
> \qquad 0 \leq \enfPar{\gamma} \leq 1.
> $$
>
> Сумма заканчивается при $k = T-t-1$, потому что её последний член содержит
> последнюю награду $R_T$.

Для конечного эпизода определение можно записать рекурсивно:

$$
\enfTgt{G}_t = R_{t+1} + \enfPar{\gamma}\,G_{t+1},
\qquad G_T = 0.
$$

Здесь $G_T=0$, поскольку после последней награды эпизод уже завершён. В этой
формуле $\enfTgt{G}_t$ — результат, который мы ищем, а
$\enfPar{\gamma}$ — коэффициент, ослабляющий вклад следующей доходности.

### Почему рекурсивная формула верна

Начинаем с определения и отделяем первое слагаемое. Во второй строке из
оставшейся суммы вынесен общий множитель $\enfPar{\gamma}$; в третьей строке
в скобках узнано определение $G_{t+1}$:

$$
\begin{aligned}
\enfTgt{G}_t
  &= R_{t+1} + \enfOp{\sum}_{k=1}^{T-t-1}
     \enfPar{\gamma}^{k} R_{t+k+1} \\
  &= R_{t+1} + \enfPar{\gamma}
     \sum_{j=0}^{T-(t+1)-1}\gamma^j R_{(t+1)+j+1} \\
  &= R_{t+1} + \enfPar{\gamma}\,G_{t+1}.
\end{aligned}
$$

При переходе ко второй строке сделана замена индекса $j=k-1$ и вынесен
множитель $\enfPar{\gamma}$: поэтому новый счётчик начинается с нуля, а
верхний предел становится $T-(t+1)-1$. Это ровно сумма для доходности,
начинающейся на следующем шаге.

## Разобранный числовой пример

Рассмотрим эпизод из $T=4$ наград:

$$
R_1=1,\qquad R_2=0,\qquad R_3=0,\qquad R_4=10,
\qquad \enfPar{\gamma}=0{,}9.
$$

Доходность в начале эпизода равна

$$
\begin{aligned}
\enfTgt{G}_0
  &= 1 + 0{,}9 \cdot 0 + 0{,}9^2 \cdot 0
     + 0{,}9^3 \cdot 10 \\
  &= 1 + 7{,}29 \\
  &= 8{,}29.
\end{aligned}
$$

Далёкая награда 10 влияет на результат не полностью, а с весом
$0{,}9^3=0{,}729$. Поэтому её вклад составляет $7{,}29$.

## От формулы к коду

**Таблица 2. Соответствие математики и Python.**

| Символ | Смысл | В коде | Тип и форма |
|---|---|---|---|
| $\enfTgt{R}_{k+1}$ | награда на шаге $k+1$ | `rewards[k]` | `float`, элемент списка длины `T` |
| $\enfPar{\gamma}$ | коэффициент дисконтирования | `gamma` | `float` |
| $T$ | число наград в эпизоде | `T = len(rewards)` | `int` |
| $\enfTgt{G}_0$ | доходность в начале эпизода | `G0`, `G0_vec` | `float` |
| $\enfTgt{G}_t$ | все доходности эпизода | `G[t]` | `np.ndarray` формы `(T,)` |
| $\enfTgt{G}_{t+1}$ | доходность следующего шага во время обратного прохода | `running` | `float` |
| $\enfPar{\gamma}^{k}$ | вес награды с индексом $k$ | `discounts[k]` | `np.ndarray` формы `(T,)` |
| $k$, $t$ | индексы суммы и обратного прохода | `k`, `t` | `int` |

> [!warning] Сдвиг индексов
> В формулах награды нумеруются с единицы: $R_1, \dots, R_T$. Списки Python
> нумеруются с нуля, поэтому награда $R_{k+1}$ хранится в `rewards[k]`.
> Индекс $t$ в `G[t]` уже совпадает с математическим индексом $t$.

> [!note] Запятая и точка
> В русском тексте и формулах дробная часть отделяется запятой, например
> $0{,}9$. В коде Python и в его выводе используется точка: `0.9`.

### Шаг 1. Данные из ручного расчёта

Первый блок подключает NumPy и задаёт те же числа, что использовались в
ручном расчёте. Код урока выполняется сверху вниз, поэтому последующие блоки
используют эти переменные.

```python
import numpy as np

np.set_printoptions(precision=4, suppress=True, floatmode="fixed")

rewards = [1.0, 0.0, 0.0, 10.0]  # R_1, R_2, R_3, R_4
gamma = 0.9
```

Настройка печати выводит дробные числа ровно с четырьмя знаками после точки:
так результат удобно сверять с ручным расчётом.

### Шаг 2. Сумма из определения

Переводим определение буквально: одна итерация цикла добавляет одно
слагаемое $\enfPar{\gamma}^{k}R_{k+1}$.

```python
def discounted_return(rewards: list[float], gamma: float) -> float:
    """Доходность G_0: сумма gamma**k * R_{k+1}."""
    G = 0.0                          # (1)
    for k, r in enumerate(rewards):  # (2)
        G += gamma**k * r            # (3)
    return G


G0 = discounted_return(rewards, gamma)
print(f"G_0 = {G0:.4f}")
```

```output
G_0 = 8.2900
```

**Разбор.**

1. `G` — накопитель суммы. До добавления первого слагаемого сумма равна
   нулю.
2. `enumerate` выдаёт пары «номер, элемент»: `k` — показатель степени в
   $\enfPar{\gamma}^{k}$, а `r` — награда $R_{k+1}$.
3. Оператор `**` возводит `gamma` в степень `k`, после чего результат
   умножается на текущую награду и добавляется к накопителю.

Получили $8{,}29$ — то же значение, что и в ручном расчёте.

### Шаг 3. Все доходности обратным проходом

Если считать сумму из определения для каждого $t$ отдельно, одни и те же
хвосты последовательности будут складываться многократно. Рекурсивная
формула позволяет пройти эпизод один раз — от последней награды к первой.

```python
def returns_backward(rewards: list[float], gamma: float) -> np.ndarray:
    """Все G_t по рекурсии G_t = R_{t+1} + gamma * G_{t+1}."""
    T = len(rewards)
    G = np.zeros(T)                             # (1)
    running = 0.0                               # (2)
    for t in range(T - 1, -1, -1):              # (3)
        running = rewards[t] + gamma * running  # (4)
        G[t] = running
    return G


G = returns_backward(rewards, gamma)
assert G.shape == (len(rewards),)
print("G =", G)
```

```output
G = [ 8.2900  8.1000  9.0000 10.0000]
```

**Разбор.**

1. `G` — массив из `T` нулей. После цикла в `G[t]` хранится доходность
   $G_t$.
2. `running` хранит доходность следующего шага. До начала цикла это
   $G_T=0$, потому что после конца эпизода наград нет.
3. `range(T - 1, -1, -1)` перечисляет индексы в порядке `3, 2, 1, 0`.
   Правая граница `-1` не входит в диапазон, а последний аргумент задаёт шаг.
4. Строка дословно реализует рекурсию: справа `running` ещё равно
   $G_{t+1}$, а после присваивания слева уже содержит $G_t$.

Трассировка цикла подтверждает каждое обновление.

**Таблица 3. Трассировка обратного прохода.**

| Итерация | `t` | `rewards[t]` | `running` до | `running` после, $G_t$ |
|:-:|:-:|:-:|:-:|:-:|
| 1 | `3` | `10.0` | `0.0000` | `10.0000` |
| 2 | `2` | `0.0` | `10.0000` | `9.0000` |
| 3 | `1` | `0.0` | `9.0000` | `8.1000` |
| 4 | `0` | `1.0` | `8.1000` | `8.2900` |

### Шаг 4. Векторная запись и проверка

Для $G_0$ сумма из определения является скалярным произведением вектора
весов $(1, \enfPar{\gamma}, \gamma^2, \gamma^3)$ и вектора наград. NumPy
записывает это действие оператором `@`; явный цикл не нужен.

```python
T = len(rewards)
discounts = gamma ** np.arange(T)       # (1)
G0_vec = discounts @ np.array(rewards)  # (2)

print("discounts =", discounts)
print(f"G_0 = {G0_vec:.4f}")

assert np.isclose(G0_vec, G0)           # (3)
assert np.isclose(G[0], G0)
```

```output
discounts = [1.0000 0.9000 0.8100 0.7290]
G_0 = 8.2900
```

**Разбор.**

1. `np.arange(T)` создаёт индексы `[0, 1, 2, 3]`. Возведение числа в степень
   массива выполняется поэлементно, поэтому `discounts` содержит все веса
   $\enfPar{\gamma}^{k}$.
2. Оператор `@` вычисляет скалярное произведение, то есть всю сумму
   $\enfOp{\sum}_k \gamma^k R_{k+1}$. Оператор `*` перемножил бы векторы
   поэлементно и вернул массив, а не одно число.
3. `np.isclose` проверяет совпадение чисел с допустимой погрешностью.
   Такое сравнение нужно для чисел с плавающей точкой: их двоичная запись
   может не представлять десятичную дробь точно.

Три представления — ручной расчёт, прямой цикл и векторное произведение —
дали одно значение. Следовательно, формула и код согласованы на этом примере.

> [!warning] Типичная ошибка: `^` вместо `**`
>
> ```python
> print(gamma ^ 2)
> ```
>
> ```output
> TypeError: unsupported operand type(s) for ^: 'float' and 'int'
> ```
>
> В Python `^` означает побитовое исключающее «или» и не возводит число в
> степень. Для возведения в степень используется `**`.

4. Измените список `rewards` так, чтобы дальняя награда стала отрицательной.

> [!example] Решение упражнения 1
>
> ```python
> print(f"G_0 = {discounted_return(rewards, 0.5):.4f}")
> ```
>
> ```output
> G_0 = 2.2500
> ```
>

> равны нулю. Уменьшение коэффициента ослабило влияние дальней награды.

## Итоги

1. Дисконтированная доходность складывает будущие награды с весами
   $1, \gamma, \gamma^2, \dots$.
2. Рекурсия $G_t=R_{t+1}+\gamma G_{t+1}$ получается отделением первой
   награды в определяющей сумме.
3. Обратный проход вычисляет все $G_t$ за один просмотр списка наград справа
   налево.
4. Цикл, рекурсивный расчёт и векторное произведение должны давать один
   результат; это удобно проверять через `np.isclose`.

**Таблица 4. Итоговое соответствие формулы и кода.**

| Математика | Python |
|---|---|
| $\enfOp{\sum}_k \gamma^k R_{k+1}$ | цикл `for k, r in enumerate(rewards)` или `discounts @ np.array(rewards)` |
| $G_t = R_{t+1} + \gamma G_{t+1}$ | обратный цикл `for t in range(T - 1, -1, -1)` |
| $G_T = 0$ | `running = 0.0` перед циклом |
| $\gamma^k$ для всех $k$ | `gamma ** np.arange(T)` |
