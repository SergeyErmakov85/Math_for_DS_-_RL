# Ermakov Notes Framework (ENF)

**Открытый фреймворк для создания научных и образовательных материалов по математике, Data Science и Reinforcement Learning.**

Это не набор шаблонов, а целостная экосистема: руководство по стилю с нумерованными правилами, готовое хранилище Obsidian, библиотеки диаграмм, конвейер публикации в пять форматов и инструменты контроля качества, рассчитанные на работу совместно с ИИ-агентами.

## Зачем это нужно

Преподаватель, который годами пишет лекции, книги и задачники, сталкивается с одними и теми же проблемами: цвета в формулах выбираются каждый раз заново, одна и та же диаграмма рисуется в третий раз, документ хорошо выглядит в Obsidian и разваливается при экспорте в PDF, а ИИ-помощник каждый раз получает объяснение требований с нуля.

ENF решает эти проблемы четырьмя решениями:

1. **Единый источник истины.** Палитра, терминология и правила определяются один раз (`docs/style/`) и переиспользуются в Obsidian, SVG, Mermaid и Pandoc-шаблонах.
2. **Два режима раскраски формул.** *Learning Mode* — подробная семантическая раскраска для изучения новой темы; *Publication Mode* — сдержанная раскраска для книг и статей. Режим указывается во фронтматтере документа и проверяется автоматически.
3. **Двойная совместимость.** Каждая конструкция обязана одинаково работать в Obsidian (MathJax) и в Pandoc-сборке. Приём, ломающий хотя бы один из пяти форматов, во фреймворк не принимается.
4. **Нумерованные правила.** Каждое правило имеет идентификатор вида `ENF-STYLE-001`, на который ссылаются чек-листы, промты и автоматические проверки. Спор о вкусе превращается в ссылку на номер.

## Быстрый старт

```bash
git clone https://github.com/SergeyErmakov85/Math_for_DS_-_RL.git
cd Math_for_DS_-_RL
```

**Писать материалы.** Скопируйте нужный шаблон из `templates/` и заполните его:

```bash
cp templates/Lecture.md "Лекция 01 — Предел функции.md"
```

**Работать в Obsidian.** Откройте корень репозитория `Math_for_DS_&_RL` как хранилище (**Open folder as vault**) — тема, CSS-сниппеты формул, коллаутов и кода, плагин MathJax и формат ссылок уже настроены. Подробности — в [`docs/04_Obsidian_Guide.md`](docs/04_Obsidian_Guide.md).

**Проверить качество.** Уровень 1 (машинные проверки) запускается одной командой:

```powershell
pwsh Scripts/check.ps1 examples/
```

**Собрать во все форматы.** PDF, EPUB, HTML, DOCX и Reveal.js-презентация из одного Markdown-источника:

```powershell
pwsh Scripts/build.ps1 -Source examples/Bellman_Equation.md -All
```

Требования к окружению и установка зависимостей — в [`docs/11_Build_Pipeline.md`](docs/11_Build_Pipeline.md).

## Ключевая идея: два режима раскраски

Цвет во фреймворке закрепляется за **ролью** сущности, а не за конкретным символом. Буква $x$ окрашивается как переменная не потому, что это «икс», а потому, что в данной формуле она играет роль переменной; в другой формуле та же буква может быть параметром и получит другой цвет.

Режим документа задаётся во фронтматтере:

```yaml
---
enf_mode: learning      # или publication
---
```

В *Learning Mode* выделяется почти каждая значимая сущность — читатель быстрее формирует визуальные ассоциации. В *Publication Mode* выделяются только ключевые роли: в длинных выводах (уравнение Беллмана, формула Байеса, многомерная оптимизация) избыточная раскраска ухудшает читаемость, а не улучшает её.

Правило «раскрашивать каждый символ всегда» во фреймворке прямо запрещено — см. `ENF-MATH-020` в [`docs/03_Math_Notation.md`](docs/03_Math_Notation.md).

## Доступность

Цвет никогда не является единственным носителем смысла. Все токены палитры проверены на контраст не ниже WCAG AA на светлом и тёмном фоне и на различимость при дейтеранопии и протанопии; смысл дублируется начертанием, символом или подписью. Проверка контраста воспроизводится командой:

```powershell
node Scripts/check-contrast.mjs
```
