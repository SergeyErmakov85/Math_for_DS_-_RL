# § 3. Градиентный спуск и оптимизация

## Зачем это нужно

Градиент указывает направление наискорейшего роста. Обучение — это уменьшение потерь, значит идти надо в противоположную сторону. Отсюда алгоритм в одну строку, на котором работает практически всё машинное обучение, включая обучение политик в ML-Agents.

Простота обманчива. Алгоритм задаёт направление, но не длину шага, а от неё зависит всё: слишком большой шаг разносит обучение, слишком малый растягивает его на недели. Кроме того, направление верно лишь локально — ровно там, где линейное приближение из [§ 1](01-derivatives.md) ещё работает. Раздел разбирает и сам метод, и три его варианта, различающиеся тем, по скольким данным считается градиент.

## Обозначения

| Символ | Значение | Роль |
|--------|----------|------|
| $\enfPar{\theta} \in \mathbb{R}^{d}$ | вектор параметров модели | `parameter` |
| $\enfPar{\alpha}$ | скорость обучения (learning rate) | `parameter` |
| $\enfVar{\mathbf{x}}_i, \enfTgt{y}_i$ | признаки и правильный ответ объекта $i$ | `variable`, `target` |
| $\enfTgt{\mathcal{L}}(\enfPar{\theta})$ | функция потерь | `target` |
| $\enfOp{\nabla}\enfTgt{\mathcal{L}}$ | градиент функции потерь | `operator` |
| $\enfVar{B}$ | мини-батч — подмножество обучающих объектов | `variable` |
| $\enfOp{H}$ | матрица Гессе | `operator` |

## Основное правило

> [!definition] Определение 1. Градиентный спуск
> **Градиентный спуск** (gradient descent) — итерационный метод минимизации, задаваемый правилом
> $$\enfPar{\theta}_{k+1} = \enfPar{\theta}_{k} - \enfPar{\alpha}\,\enfOp{\nabla}\enfTgt{\mathcal{L}}(\enfPar{\theta}_{k}).$$
> Величина $\enfPar{\alpha} > 0$ называется **скоростью обучения** (learning rate).

Обоснование правила — прямо из линейного приближения. Вблизи текущей точки

$$
\enfTgt{\mathcal{L}}(\enfPar{\theta} + \Delta\enfPar{\theta}) \approx \enfTgt{\mathcal{L}}(\enfPar{\theta}) + \enfOp{\nabla}\enfTgt{\mathcal{L}} \cdot \Delta\enfPar{\theta}.
$$

Подставив $\Delta\enfPar{\theta} = -\enfPar{\alpha}\,\enfOp{\nabla}\enfTgt{\mathcal{L}}$, получаем изменение потерь $-\enfPar{\alpha}\,\lVert \enfOp{\nabla}\enfTgt{\mathcal{L}} \rVert^{2} \le 0$: потери гарантированно убывают. Гарантия действует, только пока приближение верно, то есть при достаточно малом $\enfPar{\alpha}$ — вся практика настройки скорости обучения умещается в эту оговорку.

## Сколько данных берётся на один шаг

Функция потерь на выборке — среднее по объектам, поэтому и градиент есть среднее градиентов. Считать это среднее можно по-разному.

*Таблица 1. Три варианта градиентного спуска.*

| Вариант | Объектов на шаг | Свойства | Где применяется |
|---|---|---|---|
| Пакетный (batch) | вся выборка | точный градиент, гладкая траектория, дорогой шаг | малые задачи, теоретический анализ |
| Стохастический (SGD) | один | очень шумный, дешёвый шаг, шум помогает выйти из плато | онлайн-обучение |
| Мини-батчевый | от 32 до нескольких тысяч | компромисс; эффективно параллелится | стандарт, в том числе ML-Agents |

Формально мини-батчевый вариант оценивает градиент по подмножеству:

$$
\enfOp{\nabla}\enfTgt{\mathcal{L}} \approx \frac{1}{|\enfVar{B}|}\sum_{i \in \enfVar{B}} \enfOp{\nabla}\enfTgt{\mathcal{L}}_i(\enfPar{\theta}).
$$

Оценка несмещённая: математическое ожидание среднего по случайно выбранному подмножеству равно среднему по всей выборке. Смещения нет, есть дисперсия — она убывает как $1/|\enfVar{B}|$, поэтому учетверение батча уменьшает шум градиента вдвое, а не вчетверо.

> [!remark] Почему в RL мини-батч устроен иначе
> В обучении с учителем выборка фиксирована. В RL данные порождает сам агент, и распределение меняется по мере обучения. В конфигурации ML-Agents за это отвечают два параметра: `buffer_size` — сколько опыта накапливается перед обновлением, и `batch_size` — сколько берётся на один шаг градиента. Соотношение между ними задаёт, сколько раз каждый эпизод переиспользуется, — вопрос, к которому [PPO](../part-5-policy-optimization/04-ppo.md) относится особенно чувствительно.

## Скорость обучения

Выбор $\enfPar{\alpha}$ — главное решение при настройке. Разберём его на одномерной квадратичной задаче, где всё считается точно.

**Постановка.** Пусть $\enfTgt{\mathcal{L}}(\enfPar{\theta}) = \tfrac{1}{2}\,c\,\enfPar{\theta}^{2}$ при $c > 0$; минимум в нуле, градиент равен $c\,\enfPar{\theta}$.

**Шаг 1.** Подставим градиент в правило спуска:

$$
\enfPar{\theta}_{k+1} = \enfPar{\theta}_{k} - \enfPar{\alpha}\,c\,\enfPar{\theta}_{k} = (1 - \enfPar{\alpha}c)\,\enfPar{\theta}_{k}.
$$

**Шаг 2.** Это геометрическая последовательность со знаменателем $q = 1 - \enfPar{\alpha}c$. По теореме об убывании степеней из [Части I](../part-1-limits-series/01-sequence-limit.md) она стремится к нулю тогда и только тогда, когда $|q| < 1$, то есть

$$
0 < \enfPar{\alpha} < \frac{2}{c}.
$$

**Шаг 3.** Разберём режимы. При $\enfPar{\alpha} = 1/c$ знаменатель равен нулю — попадание в минимум за один шаг. При $0 < \enfPar{\alpha} < 1/c$ сходимость монотонная. При $1/c < \enfPar{\alpha} < 2/c$ знак чередуется — сходимость с колебаниями. При $\enfPar{\alpha} > 2/c$ модуль знаменателя больше единицы, и процесс расходится. $\blacksquare$

**Числовой пример.** При $c = 4$ и $\enfPar{\theta}_0 = 1$: при $\alpha = 0{,}1$ имеем $q = 0{,}6$ и последовательность $1;\ 0{,}6;\ 0{,}36;\ 0{,}216$. При $\alpha = 0{,}6$ имеем $q = -1{,}4$ и последовательность $1;\ -1{,}4;\ 1{,}96;\ -2{,}744$ — расходимость, видимая с третьего шага.

В многомерном случае роль $c$ играют собственные значения матрицы Гессе, и условие устойчивости определяется наибольшим из них: $\enfPar{\alpha} < 2/\lambda_{\max}$. При этом скорость сходимости определяется наименьшим. Отношение $\lambda_{\max}/\lambda_{\min}$ — **число обусловленности** — и есть точная мера того, насколько задача неудобна: шаг приходится выбирать по самому крутому направлению, а ждать — самое пологое.

## Расписание скорости обучения

Постоянная $\enfPar{\alpha}$ плоха по той же причине, что и в [условиях Роббинса — Монро](../part-1-limits-series/07-examples-and-tasks.md): она не даёт осесть в решении. Поэтому шаг уменьшают по ходу обучения.

- **Линейное убывание** — $\enfPar{\alpha}_k = \enfPar{\alpha}_0 (1 - k/K)$, где $K$ — общее число шагов. Именно этот вариант включён строкой `learning_rate_schedule: linear` в конфигурации RollerAgent этого репозитория при `learning_rate: 3.0e-4`.
- **Ступенчатое** — деление $\enfPar{\alpha}$ на 10 в заранее назначенные моменты.
- **Косинусное** — плавное убывание по закону косинуса, популярное в обучении с учителем.

В RL линейное расписание предпочтительнее прочих по содержательной причине: к концу обучения политика меняется мало, и распределение данных стабилизируется, поэтому уменьшение шага не мешает адаптации.

## Три типичные неприятности

**Плато и малый градиент.** Длина градиента мала, шаги почти нулевые, обучение стоит. Причина обычно не в локальном минимуме, а в седловой точке или в насыщении активаций (см. затухание градиента в [§ 1](01-derivatives.md)). Средства: нормализация входов, замена сигмоиды на ReLU, методы с импульсом.

**Овраг.** Линии уровня вытянуты, градиент указывает поперёк оврага, траектория зигзагует. Средства: нормализация признаков, приводящая масштабы к одному порядку, и адаптивные методы, разобранные в [Части V](../part-5-policy-optimization/03-gradient-descent-variants.md).

**Взрыв градиента.** Длина градиента внезапно велика, один шаг уносит параметры далеко, обучение разрушается. Стандартное средство — **обрезка градиента** (gradient clipping): если $\lVert \enfOp{\nabla}\enfTgt{\mathcal{L}} \rVert > c$, вектор масштабируется до длины $c$ с сохранением направления. В RL взрывы особенно часты, поскольку цель обучения сама зависит от текущих оценок.

## Реализация

```python
import numpy as np


def gradient_descent(grad, theta0, alpha=0.1, steps=100, tol=1e-8):
    """Градиентный спуск с остановкой по малости шага.

    grad   — функция, возвращающая градиент в точке;
    theta0 — начальное приближение (numpy-массив);
    alpha  — скорость обучения.
    """
    theta = np.array(theta0, dtype=float)
    history = [theta.copy()]
    for _ in range(steps):
        step = alpha * grad(theta)
        theta = theta - step
        history.append(theta.copy())
        if np.linalg.norm(step) < tol:
            break
    return theta, np.array(history)


if __name__ == "__main__":
    # L(t) = 0.5 * (5 t0^2 + 0.5 t1^2): вытянутые линии уровня.
    scale = np.array([5.0, 0.5])
    result, hist = gradient_descent(lambda t: scale * t, [1.0, 1.0], alpha=0.3)
    print(f"итераций: {len(hist) - 1}, результат: {result}")
```

Запуск показывает характерную картину оврага: первая координата с $\lambda = 5$ и $\alpha = 0{,}3$ даёт знаменатель $1 - 1{,}5 = -0{,}5$ и колеблется, затухая; вторая с $\lambda = 0{,}5$ даёт знаменатель $0{,}85$ и ползёт медленно. Одно значение $\alpha$ обслуживает оба направления плохо — число обусловленности здесь равно 10.

## Что стоит запомнить

1. Градиентный спуск обоснован линейным приближением, поэтому его гарантия убывания действует лишь при достаточно малом шаге.
2. Мини-батчевая оценка градиента несмещена; её шум убывает как $1/|B|$, то есть вчетверо больший батч даёт вдвое меньший шум.
3. В квадратичной задаче условие устойчивости — $\alpha < 2/\lambda_{\max}$, а скорость определяется $\lambda_{\min}$; отношение этих чисел и есть число обусловленности.
4. Постоянная скорость обучения оставляет колебания вокруг решения, поэтому применяют расписания; в конфигурации RollerAgent используется линейное.
5. Плато, овраг и взрыв градиента — три разные болезни с разными лекарствами; путать их дорого.

2. Батч увеличили с 64 до 1024. Во сколько раз уменьшился шум оценки градиента и во сколько раз вырос объём вычислений на шаг?
3. Собственные значения Гессе равны 100 и 1. Какое $\alpha$ допустимо и сколько шагов примерно потребуется по медленному направлению?
4. Запустите приведённый код с `alpha=0.45`. Что произойдёт с первой координатой и почему это следует из условия устойчивости?
5. Обучение агента идёт устойчиво, но резко разрушается на 200-й тысяче шагов. Какая из трёх неприятностей наиболее вероятна и какое средство применить первым?
