# 6. Практические примеры (Python)

## Зачем это нужно

Утверждения предыдущих разделов проверяемы численно, и проверять их стоит. Закон больших чисел говорит, что среднее сходится, — за десять строк кода видно, как именно и насколько медленно. Формула $\sigma/\sqrt{n}$ обещает определённую точность — эксперимент показывает, что обещание выполняется буквально.

Второе назначение раздела практическое: три примера образуют минимальный набор инструментов для работы с любым обучением. Симуляция проверяет гипотезу о случайной величине, анализ наград оценивает качество агента с доверительным интервалом, оценка политики даёт точный ответ там, где среда мала настолько, что итерации не нужны.

Код требует только `numpy`; все листинги самодостаточны и запускаются как есть.

## Обозначения

| Символ | Значение | Роль |
|--------|----------|------|
| $\enfVar{n}$ | число испытаний или эпизодов | `variable` |
| $\enfPar{p}$ | вероятность успеха | `parameter` |
| $\enfPar{\gamma}$ | коэффициент дисконтирования | `parameter` |
| $\enfOp{\bar{x}}$ | выборочное среднее | `operator` |
| $\enfOp{V}$ | функция ценности | `operator` |
| $\enfTgt{r}$ | награда | `target` |

## Симуляция бросков монеты

Проверим закон больших чисел и скорость сходимости.

```python
import numpy as np

rng = np.random.default_rng(42)
P_TRUE = 0.3
N = 100_000

flips = rng.random(N) < P_TRUE          # True с вероятностью 0.3
running_mean = np.cumsum(flips) / np.arange(1, N + 1)

for n in (10, 100, 1_000, 10_000, 100_000):
    estimate = running_mean[n - 1]
    theoretical_se = np.sqrt(P_TRUE * (1 - P_TRUE) / n)
    print(f"n = {n:>7}: оценка = {estimate:.4f}, "
          f"отклонение = {abs(estimate - P_TRUE):.4f}, "
          f"теор. ст. ошибка = {theoretical_se:.4f}")
```

Теоретическая стандартная ошибка для схемы Бернулли равна $\sqrt{\enfPar{p}(1-\enfPar{p})/\enfVar{n}}$, поскольку дисперсия одного испытания равна $\enfPar{p}(1-\enfPar{p})$, а дисперсия среднего в $\enfVar{n}$ раз меньше — результат из [раздела 1](01-probability-theory.md).

*Таблица 1. Ожидаемая точность оценки вероятности при $p = 0{,}3$.*

| $n$ | Стандартная ошибка | Типичное отклонение |
|---|---|---|
| 10 | 0,145 | десятые доли |
| 100 | 0,046 | сотые доли |
| 1 000 | 0,014 | около 0,01 |
| 10 000 | 0,0046 | тысячные доли |
| 100 000 | 0,0014 | около 0,001 |

Сходимость есть, но медленная: стократное увеличение выборки уменьшает ошибку лишь в десять раз. Это тот же закон $1/\sqrt{n}$, который определяет, сколько эпизодов нужно для надёжной оценки ценности.

## Анализ вознаграждений

Задача практическая: по логу наград оценить качество агента и сравнить два варианта обучения.

```python
import numpy as np

rng = np.random.default_rng(7)


def summarize(rewards, name, level=1.96):
    """Сводка по наградам: среднее, разброс, доверительный интервал."""
    rewards = np.asarray(rewards, dtype=float)
    n = rewards.size
    mean = rewards.mean()
    std = rewards.std(ddof=1)              # поправка Бесселя
    se = std / np.sqrt(n)
    lo, hi = mean - level * se, mean + level * se
    print(f"{name}: n = {n}, среднее = {mean:.2f}, s = {std:.2f}, "
          f"95% ДИ = [{lo:.2f}, {hi:.2f}], медиана = {np.median(rewards):.2f}")
    return mean, se


# Два варианта обучения: 20 прогонов каждый.
agent_a = rng.normal(loc=45.0, scale=8.0, size=20)
agent_b = rng.normal(loc=52.0, scale=9.0, size=20)

mean_a, se_a = summarize(agent_a, "вариант A")
mean_b, se_b = summarize(agent_b, "вариант B")

diff = mean_b - mean_a
se_diff = np.sqrt(se_a ** 2 + se_b ** 2)
z = diff / se_diff
print(f"разность = {diff:.2f}, ст. ошибка разности = {se_diff:.2f}, z = {z:.2f}")
print("различие значимо на уровне 0.05" if abs(z) > 1.96 else "различие не установлено")
```

Три детали листинга существенны.

- **`ddof=1`** включает поправку Бесселя. Без неё дисперсия систематически занижается, а доверительный интервал получается уже, чем следует, — то есть выводы выглядят увереннее, чем есть на самом деле.
- **Медиана печатается рядом со средним.** Их расхождение указывает на несимметричное распределение наград — например, на редкие катастрофические эпизоды, которые среднее скрывает.
- **Стандартная ошибка разности** равна корню из суммы квадратов, а не сумме: складываются дисперсии, а не отклонения.

> [!warning] Двадцать прогонов — минимум, а не роскошь
> При типичном для RL разбросе в 15–20 % от среднего трёх прогонов не хватает, чтобы обнаружить даже десятипроцентное улучшение. Публикуемые кривые обучения по трём запускам — основной источник невоспроизводимых результатов в литературе.

## Оценка политики в MDP

Третий пример решает уравнение Беллмана двумя способами и сверяет ответы: точно — обращением матрицы, приближённо — итерациями.

```python
import numpy as np

GAMMA = 0.9

# Среда: 3 состояния, s2 — терминальное (петля с нулевой наградой).
# P[s, s'] — вероятность перехода при следовании политике.
P = np.array([
    [0.0, 0.8, 0.2],   # s0 -> s1 (0.8) или s2 (0.2)
    [0.0, 0.0, 1.0],   # s1 -> s2
    [0.0, 0.0, 1.0],   # s2 -> s2 (терминальное)
])

# Ожидаемая награда за шаг из каждого состояния.
R = np.array([-1.0, 10.0, 0.0])


def exact_values(p_matrix, rewards, gamma=GAMMA):
    """Точное решение уравнения Беллмана: v = (I - gamma P)^-1 r."""
    n = rewards.size
    return np.linalg.solve(np.eye(n) - gamma * p_matrix, rewards)


def iterative_values(p_matrix, rewards, gamma=GAMMA, tol=1e-10, max_steps=10_000):
    """Итеративная оценка политики: v <- r + gamma P v."""
    v = np.zeros_like(rewards)
    for step in range(1, max_steps + 1):
        v_next = rewards + gamma * p_matrix @ v
        if np.max(np.abs(v_next - v)) < tol:
            return v_next, step
        v = v_next
    raise RuntimeError("сходимость не достигнута")


v_exact = exact_values(P, R)
v_iter, steps = iterative_values(P, R)

print("точное решение:      ", np.round(v_exact, 6))
print(f"итеративное ({steps} шагов):", np.round(v_iter, 6))
print("максимальное расхождение:", np.abs(v_exact - v_iter).max())
```

**Разбор ответа.** Терминальное состояние зациклено на себя с нулевой наградой, поэтому его ценность равна нулю. Для $\enfVar{s}_1$ получаем $\enfOp{V} = 10 + 0{,}9\cdot 0 = 10$. Для $\enfVar{s}_0$:

$$
\enfOp{V}(\enfVar{s}_0) = -1 + 0{,}9\,(0{,}8 \cdot 10 + 0{,}2 \cdot 0) = -1 + 0{,}9 \cdot 8 = 6{,}2.
$$

Оба метода дают $(6{,}2;\ 10;\ 0)$. Совпадение — не формальность: расхождение указало бы на ошибку в матрице переходов, чаще всего на строку, не суммирующуюся к единице.

> [!remark] Какой способ выбирать
> Прямое решение точно и быстро при числе состояний до нескольких тысяч. Дальше матрица $\mathbf{I} - \gamma\mathbf{P}$ перестаёт помещаться в память, и остаются итерации, чья стоимость на шаг линейна по числу ненулевых переходов. Для GridWorld 5×5 этого репозитория — 25 состояний — годится любой способ, для среды с миллионом состояний только итерационный.

## Упражнения для самопроверки

**Упражнение 1.** Измените `P_TRUE` на 0,05 и запустите первый листинг. Почему при малой вероятности та же точность требует большего числа испытаний? Проверьте ответ формулой стандартной ошибки.

**Упражнение 2.** Во втором листинге замените размер выборки с 20 на 5 и запустите несколько раз с разными зерном генератора. Как часто вывод о значимости меняется? Что это говорит о выводах по пяти прогонам?

**Упражнение 3.** Добавьте в функцию `summarize` вычисление 10-го и 90-го процентилей (`np.percentile`). Сгенерируйте выборку, где 10 % эпизодов дают награду $-100$, а остальные $+50$. Сравните, что сообщают среднее и процентили.

**Упражнение 4.** В третьем листинге сделайте среду циклической: пусть из $\enfVar{s}_2$ агент возвращается в $\enfVar{s}_0$ с наградой $0$. Пересчитайте ценности обоими способами и объясните, почему они выросли.

**Упражнение 5.** Установите в третьем листинге `GAMMA = 1.0` для циклической версии из упражнения 4. Что произойдёт с обоими методами и как это связано с расходимостью возврата из [Части I](../part-1-limits-series/03-limits-in-rl.md)?

**Ответы к упражнениям 1 и 5.** В первом: при $p = 0{,}05$ дисперсия одного испытания равна $0{,}0475$ против $0{,}21$ при $p = 0{,}3$, то есть абсолютная ошибка меньше, но **относительная** — по отношению к самой оценке — существенно больше. Относительная ошибка пропорциональна $\sqrt{(1-p)/(p\,n)}$, поэтому для той же относительной точности число испытаний масштабируется как $(1-p)/p$: отношение $19$ к $2{,}33$ даёт примерно восьмикратный рост. В пятом: матрица $\mathbf{I} - \mathbf{P}$ вырождена, `np.linalg.solve` сообщит о сингулярности либо вернёт мусор, а итерации не сойдутся и упрутся в предел числа шагов — оба симптома отражают отсутствие конечного возврата в бесконечном цикле с ненулевой наградой.

## Что стоит запомнить

1. Закон больших чисел проверяется в десять строк, и эксперимент показывает медленность сходимости нагляднее любой формулы.
2. Стандартная ошибка $\sigma/\sqrt{n}$ переводит «агент набрал 45» в проверяемое «45 с интервалом от 41 до 49».
3. Поправка Бесселя (`ddof=1`) обязательна: без неё доверительные интервалы систематически занижены.
4. Медиана и процентили рядом со средним выявляют редкие катастрофические эпизоды, которые среднее скрывает.
5. Оценку политики стоит считать двумя способами и сверять: расхождение указывает на ошибку в модели среды раньше, чем на неё укажет обучение.
