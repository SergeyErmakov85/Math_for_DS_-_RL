# Build — конфигурация Pandoc-сборки

Из одного Markdown-источника собираются пять форматов: PDF, EPUB, HTML, DOCX и Reveal.js-презентация.

| Каталог / файл | Содержимое |
|----------------|------------|
| [`defaults/`](defaults/) | Файлы `--defaults` Pandoc — по одному на формат |
| [`templates/`](templates/) | LaTeX-преамбула, порождаемые цвета, макросы MathJax |
| [`filters/`](filters/) | Lua-фильтры: коллауты, цвет формул, обработка SVG |
| [`css/`](css/) | `enf-tokens.css` — единый источник цветов; `enf-html.css` — оформление HTML, EPUB и слайдов |
| `metadata.yaml` | Общие метаданные: язык, полоса набора, оглавление |

## Установка зависимостей

Проверено «с нуля» на Windows 11.

| Зависимость | Минимальная версия | Установка | Без неё |
|-------------|--------------------|-----------|---------|
| Pandoc | 2.19 | `winget install JohnMacFarlane.Pandoc` | не собирается ничего |
| MiKTeX или TeX Live | любая актуальная | `winget install MiKTeX.MiKTeX` | не собирается PDF |
| Node.js | 18 | `winget install OpenJS.NodeJS.LTS` | не работают проверки и генераторы |
| PowerShell | 7 | `winget install Microsoft.PowerShell` | не работает оркестрация |
| rsvg-convert или Inkscape | любая | `winget install Inkscape.Inkscape` | PDF собирается, но вместо иллюстраций рамки с alt-текстом |

Проверка готовности:

```powershell
pwsh Scripts/build.ps1 -CheckEnv
```

Команда печатает найденные версии и явно сообщает, какого инструмента не хватает для какого формата.

## Почему XeLaTeX, а не pdfLaTeX

Содержимое материалов на русском. pdfLaTeX требует ручной настройки кодировок и плохо переносит смешение кириллицы с математикой; XeLaTeX работает с системными Unicode-шрифтами напрямую. Движок задан в `defaults/pdf.yaml` и в отдельных документах не переопределяется (`ENF-PUB-020`).

## Шрифты подбираются, а не назначаются

В `metadata.yaml` гарнитуры **не заданы** намеренно. Пакет `fontspec` не подставляет замену: названный, но не установленный шрифт останавливает сборку PDF с ошибкой «font cannot be found». Список желаемых шрифтов в конфигурации означал бы, что документ собирается только на машине автора.

Поэтому `Scripts/build.ps1` перечисляет установленные в системе гарнитуры и выбирает первую доступную из списка кандидатов:

| Роль | Кандидаты по убыванию предпочтения |
|------|------------------------------------|
| основной текст | Charter, PT Serif, Georgia, Cambria, DejaVu Serif, Liberation Serif, Times New Roman |
| заголовки | Inter, PT Sans, Segoe UI, DejaVu Sans, Liberation Sans, Arial |
| код | JetBrains Mono, Consolas, DejaVu Sans Mono, Liberation Mono, Courier New |
| формулы | Latin Modern Math, STIX Two Math, XITS Math, Cambria Math |

Все кандидаты покрывают кириллицу. Гарнитура без кириллицы дала бы вместо русского текста пустые прямоугольники — ошибку, которую легко не заметить, а это хуже несобравшегося PDF.

## Перенос цвета формул

В исходнике раскраска пишется макросами ролей (`\enfVar`, `\enfFun`, `\enfPar`, `\enfOp`, `\enfTgt`), а не HEX-кодами. Дальше цвет разрешается по-разному:

| Формат | Механизм |
|--------|----------|
| Obsidian | макросы MathJax из преамбулы хранилища |
| HTML, Reveal.js | те же макросы (`templates/mathjax-macros.html`) плюс `css/enf-tokens.css` |
| PDF | `\definecolor` и `\newcommand` из порождаемого `templates/enf-colors.tex` |
| EPUB | предрендеренные формулы MathML, цвета из CSS |
| DOCX | **цвет снимается** фильтром `filters/enf-color.lua` |

Word не поддерживает цвет внутри формул OMML: оставленный макрос попал бы в документ видимым текстом «\enfVar». Это ограничение формата, а не дефект сборки — и главная причина, по которой действует `ENF-COLOR-003`, требующее дублировать смысл цвета словами.

## SVG в PDF

LaTeX не вставляет SVG напрямую. Pandoc пытается вызвать внешний конвертер, и без него сборка PDF падала бы целиком из-за одной иллюстрации.

Фильтр `filters/enf-svg.lua` делает поведение предсказуемым:

1. если рядом с `.svg` лежит одноимённый `.pdf` — подставляется он;
2. если нет — иллюстрация заменяется рамкой с её alt-текстом, а в вывод сборки печатается предупреждение с именем файла.

Векторные копии создаются командой:

```powershell
pwsh Scripts/convert-svg.ps1
```

Второй случай — сознательная деградация, а не молчаливая потеря. Именно поэтому alt-текст обязан описывать содержание, а не называть тип объекта (`ENF-DIAG-030`): в PDF без конвертера он остаётся единственным носителем смысла иллюстрации.

## Порождаемые файлы

Не редактируются вручную (`ENF-PUB-032`):

| Файл | Генератор |
|------|-----------|
| `templates/enf-colors.tex` | `Scripts/gen-latex-colors.mjs` |
| `../Mermaid/init-config.md` и init-строки шаблонов | `Scripts/gen-mermaid-init.mjs` |
| `../Obsidian/Vault/.obsidian/snippets/enf-tokens.css` | `Scripts/gen-obsidian-css.mjs` |

Все три пересоздаются автоматически перед каждой сборкой.

## Замечание о версии Pandoc

В `defaults/html.yaml` и `defaults/revealjs.yaml` используется `self-contained`, а не `embed-resources`: второй появился в Pandoc 3, а целевое окружение проверялось на 2.19. При переходе на Pandoc 3 флаг стоит заменить — старый работает, но помечен устаревшим.
