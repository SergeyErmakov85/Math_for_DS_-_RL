# Модуль «Код»: Python в лекциях и параграфах учебника

Версия 1.0 · сентябрь 2026 · дополнение к основной инструкции проекта по созданию лекций и параграфов

## 0. Назначение и границы

**Назначение.** Модуль задаёт правила для `.md`-файлов, в которых математическое изложение сопровождается кодом на Python: лекций, параграфов учебника, практических разделов. Цель — чтобы код читался как второй язык той же мысли. Ученик видит формулу, видит её перевод на Python, запускает его и получает то же число, что и в ручном расчёте.

**Границы.** Всё, что касается текста и математики — структура параграфа, нотация, оформление и цветовая разметка формул, выноски, метаданные, стиль изложения, — определяется основной инструкцией и здесь не повторяется. Модуль добавляет правила для кода, его объяснения, вывода и связи «формула ↔ код».

**Приоритет.** В вопросах текста и математики приоритет у основной инструкции, в вопросах кода — у этого модуля. Если основная инструкция не допускает какой-то приём модуля (например, другой тип выноски), используется ближайший допустимый вариант.

**Обязательность.** «Должно» и «нельзя» — обязательные требования. «Рекомендуется» — правило по умолчанию, от которого отступают только с причиной.

**Комплект файлов.**

```

## 1. Принципы

1. **Код переводит формулу.** Каждый блок реализует конкретную формулу, определение или шаг рассуждения из текста. Код, не связанный с изложением, не допускается.
2. **Код исполним.** Все блоки основного потока выполняются сверху вниз в чистом окружении без правок и дают показанный вывод.
3. **Вывод настоящий.** В блок вывода копируется результат фактического запуска. Придумывать, округлять «на глаз» или дописывать вывод нельзя.
4. **Один блок — одна мысль.** Длинная программа делится на шаги с объяснением между ними.
5. **Сначала прозрачно, потом быстро.** Первая реализация повторяет формулу буквально; векторная или библиотечная появляется после неё и сверяется с первой.
6. **Понятность важнее краткости.** Имена повторяют обозначения из формул; приёмы, скрывающие смысл, не используются.
7. **Цвет задаёт тема, а не автор.** Автор размечает смысл: тег языка, блок вывода, выноску. Фон и подсветку обеспечивают файлы темы.

## 3. Разметка блоков

### 3.1. Теги языка

Каждый огороженный блок должен иметь ровно один тег из таблицы.

| Содержимое | Тег | Как показывается |
|---|---|---|
| исполняемый код Python | `python` | с подсветкой синтаксиса |
| вывод программы, в том числе сообщение об ошибке | `output` | без подсветки, на своём фоне, с подписью «Вывод» |
| команды терминала, например `pip install` | `bash` | с подсветкой |
| конфигурация и данные | `yaml`, `toml`, `json` | с подсветкой |
| изменения в коде «было → стало» | `diff` | строки `+` и `-` выделены |
| прочий моноширинный текст: дерево папок, схема | `text` | без подсветки |

### 3.2. Что запрещено

- Блок без тега и псевдонимы вместо канонических тегов (`py`, `python3`, `sh`, `console`).
- Любые атрибуты после тега: ```` ```{.python .numberLines} ````, ```` ```python title="..." ````. Obsidian такой блок не подсвечивает, а pandoc в режиме чтения `markdown` может принять его за обычный текст.
- Приглашение `>>>` и вывод внутри блока `python`: скопированный код не запустится.
- Табуляция (только 4 пробела), HTML-теги и цветовая разметка внутри кода, эмодзи в коде, картинки и скриншоты кода вместо текста.

### 3.3. Код внутри выносок

Код в выноске не входит в основной поток: это решения упражнений, типичные ошибки, команды установки. Каждая строка выноски, включая ограждения, начинается с `> `:

````markdown
> [!warning] Типичная ошибка: `^` вместо `**`
>
> ```python
> print(gamma ^ 2)
> ```
> ```output
> TypeError: unsupported operand type(s) for ^: 'float' and 'int'
> ```
> В Python `^` — побитовое исключающее «или». Степень записывается как `**`.
````

Между строкой заголовка выноски и её телом должна стоять пустая строка `>`, если тело начинается с текста. Без неё фильтр сборки читает заголовок и текст как один абзац и печатает всё полужирным заголовком. Obsidian такую запись показывает так же.

Такой код не становится ячейкой ноутбука и не выполняется при прогоне урока целиком, поэтому только здесь допустим код, который падает.

### 3.4. Код и математика в тексте

- Имя из кода в тексте всегда пишется в обратных кавычках: `gamma`, `G[t]`, `np.arange`.
- Математический объект всегда пишется в `$...$`: $\gamma$, $G_t$. Смешивать нельзя: ни `$gamma$`, ни `` `γ` ``.
- Формы массивов записываются как в Python: `(T,)`, `(n, d)`.
- В комментариях и докстрингах математика записывается ASCII-нотацией: `G_t`, `R_{t+1}`, `gamma**k`. LaTeX внутри кода не отображается, а Unicode-символы плохо переносятся в PDF.

### 3.5. Десятичный разделитель

В тексте и формулах разделитель выбирается по основной инструкции (в русском тексте — запятая, в LaTeX `0{,}9`). В коде, выводе и трассировках — только точка. При первом появлении кода в курсе это расхождение объясняется ученикам отдельной выноской.

## 4. Стиль кода

### 4.1. Версии и библиотеки

Код пишется для Python 3.10 и новее; целевая версия указывается в метаданных, рекомендуется 3.12. Базовый набор: NumPy 2.x и Matplotlib; для обучения с подкреплением — Gymnasium, для нейросетей — PyTorch. Каждая библиотека указывается в `code_requires`.

Устаревшие API использовать нельзя:

| Нельзя | Нужно |
|---|---|
| `np.random.seed(0)`, `np.random.rand(3)` | `rng = np.random.default_rng(0)`, `rng.random(3)` |
| `import gym` | `import gymnasium as gym` |
| `obs = env.reset()` | `obs, info = env.reset(seed=0)` |
| `obs, r, done, info = env.step(a)` | `obs, r, terminated, truncated, info = env.step(a)` |
| `np.float`, `np.int` | `float`, `int` |
| `plt.plot(...)` в многошаговом построении | `fig, ax = plt.subplots()` и методы `ax` |

### 4.2. Оформление

- Код соответствует PEP 8, отступ — 4 пробела.
- Строка кода — не длиннее 79 символов, строка комментария или докстринга — не длиннее 72. Более длинная строка заставляет ученика прокручивать блок.
- Блок — не длиннее 25 непустых строк; более длинный делится на шаги.
- После определения функции — две пустые строки.
- Все импорты и настройки — в первом блоке параграфа, кроме случая, когда сам импорт и есть предмет объяснения.
- Первый блок задаёт печать дробных чисел: `np.set_printoptions(precision=4, suppress=True, floatmode="fixed")`. Без `floatmode="fixed"` NumPy печатает `9.` вместо `9.0000`, и новичку это кажется опечаткой.

### 4.3. Имена повторяют обозначения

| Математика | Python | Правило |
|---|---|---|
| $\gamma$, $\alpha$, $\theta$, $\varepsilon$ | `gamma`, `alpha`, `theta`, `epsilon` | греческая буква — её названием |
| $x_t$, $x^{(i)}$ | `x[t]`, `x[i]` | индекс — квадратными скобками |
| $\hat{y}$, $\bar{x}$ | `y_hat`, `x_bar` | «шляпка» и черта — суффиксом |
| $s'$, $a^{*}$ | `s_next`, `a_star` | штрих и звезда — словом |
| $\nabla_\theta J$ | `grad_theta` | оператор — словом |
| $X$, $W$, $Q$ | `X`, `W`, `Q` | заглавная буква для матрицы или таблицы — как в формуле (исключение из PEP 8) |

Нельзя:

- Unicode-имена: `γ = 0.9` синтаксически верно, но ученик не наберёт это с клавиатуры.
- Однобуквенные и служебные имена, которых нет в формулах: `a`, `tmp`, `x1`.
- Сокращения, не объяснённые в таблице соответствия.

### 4.4. Функции

У каждой функции есть аннотации типов и докстринг в одну-три строки: что вычисляется и по какой формуле. Функция возвращает результат, а печатает вызывающий код. Параметры (`gamma`, `rng`) передаются явно, глобальное изменяемое состояние не используется.

```python
def returns_backward(rewards: list[float], gamma: float) -> np.ndarray:
    """Все G_t по формуле G_t = R_{t+1} + gamma * G_{t+1}, G_T = 0."""
```

### 4.5. Комментарии

- Комментарии пишутся по-русски и объясняют, зачем нужна строка и какой части формулы она соответствует, а не пересказывают синтаксис.
- Подробное объяснение уходит в разбор под блоком, а в коде остаётся маркер `# (1)`, `# (2)`. Маркеры выравниваются в одну колонку.
- При первом появлении нетривиальной операции с массивом рядом указывается форма результата: `# форма (T, n)`.
- Нельзя: закомментированный код, комментарий к каждой строке, эмодзи.

| Плохо | Хорошо |
|---|---|
| `G += gamma**k * r  # прибавляем произведение к G` | `G += gamma**k * r  # (3)` и пункт **(3)** в разборе |

### 4.6. Случайность

- В первом блоке создаётся один генератор: `rng = np.random.default_rng(42)`; зерно дублируется в `code_seed`.
- Генератор передаётся в функции параметром.
- Если результат зависит от случайности, текст говорит, какие величины изменятся при другом зерне, а какие нет.

### 4.7. Проверки как часть объяснения

- Совпадение реализаций и ручного расчёта проверяется `assert np.isclose(...)` или `assert np.allclose(...)`.
- Формы массивов в ключевых местах проверяются: `assert X.shape == (n, d)`.
- Дробные числа не сравниваются через `==`.

## 5. Мост «формула ↔ код»

### 5.1. Таблица соответствия

Перед первым блоком кода параграф должен содержать таблицу «От формулы к коду» с колонками «Символ», «Смысл», «В коде», «Тип и форма». В таблицу входит каждый символ, который появится в коде. Сдвиг индексов (в формуле с единицы, в Python с нуля) указывается прямо в строке таблицы и отдельной выноской.

Если формулы размечаются цветом (учебный режим, Learning Mode), колонка «Символ» окрашивается теми же макросами основной инструкции (`\enfVar`, `\enfPar` и др.), что и в формулах, а колонка «В коде» остаётся без цвета. Смысловые цвета формул внутрь блоков кода не переносятся: там цвет обозначает синтаксис, и двойное кодирование сбивает.

### 5.2. Сквозной числовой пример

Числа ручного расчёта должны стать данными первого блока кода. После вывода текст явно сравнивает результат: «Получили $8{,}29$ — как в ручном расчёте». Если ручной расчёт на реальных данных невозможен, сначала код прогоняется на мини-примере из 3–5 элементов, который считается вручную.

### 5.3. Лестница реализаций

1. **Буквальная.** Циклы и чистый Python, один к одному с формулой.
2. **Векторная.** NumPy без явных циклов.
3. **Библиотечная.** SciPy, scikit-learn, PyTorch — когда это нужно по теме.

Каждая следующая ступень сверяется с предыдущей через `assert`. Первую ступень пропускают, только если сама формула записана матрично, например $\hat{y} = Xw$.

### 5.4. Типовые переводы

| Математика | Python | Ловушка |
|---|---|---|
| $\sum_{i=1}^{n} x_i$ | `x.sum()` или цикл | в формуле нумерация с 1, в Python — с 0 |
| $\prod_{i} x_i$ | `np.prod(x)` | произведение многих малых чисел обнуляется; надёжнее сумма логарифмов |
| $\frac{1}{n}\sum_{i} x_i$ | `x.mean()` | выборочное среднее — оценка $\mathbb{E}[X]$, а не само ожидание |
| $x^\top y$ | `x @ y` | `x * y` перемножает поэлементно |
| $AB$ | `A @ B` | `A * B` перемножает поэлементно |
| $A \odot B$ | `A * B` | формы должны совпадать или согласовываться |
| $\lVert x \rVert_2$ | `np.linalg.norm(x)` | для матрицы по умолчанию считается норма Фробениуса |
| $a^{b}$ | `a ** b` | `^` — побитовое «или» |
| $\ln x$, $e^{x}$ | `np.log(x)`, `np.exp(x)` | `np.log` — натуральный логарифм |
| $\log_2 x$ | `np.log2(x)` | |
| $\max_a Q(s, a)$ | `Q[s].max()` | |
| $\arg\max_a Q(s, a)$ | `np.argmax(Q[s])` | при равных значениях возвращается первый индекс; жадной политике нужен случайный выбор среди равных |
| $\mathbf{1}[x > 0]$ | `(x > 0).astype(float)` | |
| $x \sim \mathcal{N}(\mu, \sigma^2)$ | `rng.normal(mu, sigma)` | второй аргумент — $\sigma$, а не $\sigma^2$ |
| $x \sim U[a, b)$ | `rng.uniform(a, b)` | |
| $f'(x)$ численно | `(f(x + h) - f(x - h)) / (2 * h)` | $h$ порядка $10^{-5}$; слишком малое $h$ усиливает ошибки округления |

### 5.5. Итог «формула ↔ код»

Параграф завершается таблицей из двух колонок «Математика» и «Python» на 3–6 строк: какая конструкция кода реализует какую запись. Это шпаргалка, к которой ученик вернётся при решении задач.

## 6. Объяснение кода

### 6.1. Схема шага

1. **Перед блоком** — 1–3 предложения: что делаем и какую формулу реализуем.
2. **Блок `python`.**
3. **Блок `output`**, если код что-то печатает.
4. **«Разбор.»** — по маркерам из кода.
5. **Связь с математикой** — сравнение с ручным расчётом или вывод, что показал шаг.

### 6.2. Формат разбора

Разбор начинается строкой `**Разбор.**`. Каждому маркеру соответствует отдельный абзац, начинающийся с полужирного маркера. В абзаце 1–3 предложения: что делает строка, какой части формулы она соответствует, почему сделано именно так (альтернатива или ловушка). Маркеры нумеруются с единицы в каждом блоке.

```markdown
**Разбор.**

**(1)** Накопитель суммы. Пока не добавлено ни одного слагаемого, сумма равна нулю.

**(2)** `enumerate` выдаёт пары «номер, элемент»: `k` — показатель степени в $\gamma^{k}$, `r` — награда $R_{k+1}$.
```

### 6.3. Глубина объяснений

Глубина задаётся полем `code_level`.

| Уровень | Для кого | Что обязательно объясняется |
|---|---|---|
| `basic` | первое знакомство с Python | каждая новая конструкция языка: `def`, `for`, `range`, срезы, f-строки, `assert` |
| `intermediate` | уверенный Python, начало NumPy | идиомы NumPy: формы, `axis`, broadcasting, маски, `@` |
| `advanced` | уверенный NumPy | только нетривиальные решения: численная устойчивость, выбор алгоритма, скорость |

Конструкция подробно объясняется при первом появлении в параграфе; дальше достаточно ссылки «см. шаг 2».

### 6.4. Трассировка

Если код реализует рекуррентную формулу, итеративный процесс или цикл с неочевидным изменением состояния, после разбора должна идти таблица трассировки: номер итерации, значения переменных до и после. ## Дисконтированная доходность

Агент получает награды $R_1, R_2, \dots, R_T$. Доходность с момента $t$ — взвешенная сумма будущих наград, в которой дальние награды весят меньше:

$$
G_t = \sum_{k=0}^{T-t-1} \gamma^{k} R_{t+k+1}, \qquad 0 \le \gamma \le 1.
$$

Ту же величину можно выразить через доходность следующего шага:

$$
G_t = R_{t+1} + \gamma\, G_{t+1}, \qquad G_T = 0.
$$

**Ручной расчёт.** Эпизод из $T = 4$ шагов с наградами $R_1 = 1$, $R_2 = 0$, $R_3 = 0$, $R_4 = 10$ и $\gamma = 0{,}9$:

$$
G_0 = 1 + 0{,}9 \cdot 0 + 0{,}9^2 \cdot 0 + 0{,}9^3 \cdot 10 = 1 + 7{,}29 = 8{,}29.
$$

### От формулы к коду

| Символ | Смысл | В коде | Тип и форма |
|---|---|---|---|
| $R_{k+1}$ | награда на шаге $k+1$ | `rewards[k]` | `float`, элемент списка длины `T` |
| $\gamma$ | коэффициент дисконтирования | `gamma` | `float` |
| $T$ | число шагов в эпизоде | `T` | `int` |
| $G_t$ | доходность с момента $t$ | `G[t]` | массив формы `(T,)` |

> [!warning] Сдвиг индексов
>
> В формулах награды нумеруются с единицы: $R_1, \dots, R_T$. Списки в Python нумеруются с нуля, поэтому награда $R_{k+1}$ хранится в `rewards[k]`.

> [!info] Запятая и точка
>
> В тексте и формулах дробная часть отделяется запятой ($0{,}9$), в коде и выводе — только точкой (`0.9`).

### Шаг 1. Данные из ручного расчёта

Код параграфа выполняется сверху вниз. Первый блок подключает библиотеку и задаёт те же числа, что и в ручном расчёте.

```python
import numpy as np

np.set_printoptions(precision=4, suppress=True, floatmode="fixed")

rewards = [1.0, 0.0, 0.0, 10.0]  # R_1, R_2, R_3, R_4
gamma = 0.9
```

Настройка печати выводит дробные числа ровно с четырьмя знаками после точки: так результат проще сверять с ручным расчётом.

### Шаг 2. Сумма из определения

Переводим определение буквально: одна итерация цикла — одно слагаемое $\gamma^{k} R_{k+1}$.

```python
def discounted_return(rewards: list[float], gamma: float) -> float:
    """Доходность G_0 по определению: сумма gamma**k * R_{k+1}."""
    G = 0.0                          # (1)
    for k, r in enumerate(rewards):  # (2)
        G += gamma**k * r            # (3)
    return G


G0 = discounted_return(rewards, gamma)
print(f"G_0 = {G0:.4f}")
```

```output
G_0 = 8.2900
```

**Разбор.**

**(1)** Накопитель суммы. Пока не добавлено ни одного слагаемого, сумма равна нулю.

**(2)** `enumerate` выдаёт пары «номер, элемент»: `k` — показатель степени в $\gamma^{k}$, `r` — награда $R_{k+1}$.

**(3)** Слагаемое суммы. Степень в Python записывается как `**`; знак `^` означает совсем другую операцию.

Получили $8{,}29$ — как в ручном расчёте.

### Шаг 3. Все $G_t$ за один проход

Определение заново пересчитывает сумму для каждого $t$. Рекуррентная формула позволяет пройти эпизод один раз — от конца к началу.

```python
def returns_backward(rewards: list[float], gamma: float) -> np.ndarray:
    """Все G_t по формуле G_t = R_{t+1} + gamma * G_{t+1}, G_T = 0."""
    T = len(rewards)
    G = np.zeros(T)                             # (1)
    running = 0.0                               # (2)
    for t in range(T - 1, -1, -1):              # (3)
        running = rewards[t] + gamma * running  # (4)
        G[t] = running
    return G


G = returns_backward(rewards, gamma)
print("G =", G)
```

```output
G = [ 8.2900  8.1000  9.0000 10.0000]
```

**Разбор.**

**(1)** Массив из `T` нулей. После цикла в `G[t]` окажется $G_t$.

**(2)** `running` хранит доходность следующего шага. До начала цикла это $G_T = 0$: после конца эпизода наград нет.

**(3)** `range(T - 1, -1, -1)` перечисляет `t` в обратном порядке: `3, 2, 1, 0`. Второй аргумент (`-1`) в диапазон не входит, третий (`-1`) задаёт шаг.

**(4)** Рекуррентная формула дословно: справа `running` — ещё $G_{t+1}$, слева — уже $G_t$. Награда $R_{t+1}$ хранится в `rewards[t]`.

Трассировка цикла (значения округлены до четырёх знаков):

| Итерация | `t` | `rewards[t]` | `running` до | `running` после, $G_t$ |
|:-:|:-:|:-:|:-:|:-:|
| 1 | `3` | `10.0` | `0.0000` | `10.0000` |
| 2 | `2` | `0.0` | `10.0000` | `9.0000` |
| 3 | `1` | `0.0` | `9.0000` | `8.1000` |
| 4 | `0` | `1.0` | `8.1000` | `8.2900` |

### Шаг 4. Векторная запись и проверка

Сумма $\sum_k \gamma^{k} R_{k+1}$ — это скалярное произведение вектора множителей $(1, \gamma, \gamma^2, \gamma^3)$ на вектор наград. Цикл не нужен.

```python
T = len(rewards)
discounts = gamma ** np.arange(T)       # (1)
G0_vec = discounts @ np.array(rewards)  # (2)

print("discounts =", discounts)
print(f"G_0 = {G0_vec:.4f}")

assert np.isclose(G0_vec, G0)           # (3)
assert np.isclose(G[0], G0)
```

```output
discounts = [1.0000 0.9000 0.8100 0.7290]
G_0 = 8.2900
```

**Разбор.**

**(1)** `np.arange(T)` даёт `[0, 1, 2, 3]`. Число в степени массива вычисляется поэлементно — получаем $\gamma^{k}$ сразу для всех $k$.

**(2)** Оператор `@` — скалярное произведение, то есть вся сумма $\sum_k \gamma^{k} R_{k+1}$ одним действием. Оператор `*` перемножил бы векторы поэлементно и вернул массив, а не число.

**(3)** `assert` молча пропускает истинное условие и останавливает программу, если оно ложно. Дробные числа сравниваем через `np.isclose`, а не через `==`: из-за округления точное равенство ненадёжно.

Три реализации дали одно и то же число — код и формулы согласованы.

> [!warning] Типичная ошибка: `^` вместо `**`
>
> ```python
> print(gamma ^ 2)
> ```
> ```output
> TypeError: unsupported operand type(s) for ^: 'float' and 'int'
> ```
> В Python `^` — побитовое исключающее «или», оно определено только для целых чисел. Возведение в степень записывается как `**`.

> $G_0 = 1 + 0{,}5^3 \cdot 10 = 2{,}25$. Чем меньше $\gamma$, тем слабее далёкая награда влияет на доходность.

### Итог: формула ↔ код

| Математика | Python |
|---|---|
| $\sum_{k} \gamma^{k} R_{k+1}$ | цикл `for k, r in enumerate(rewards)` или `discounts @ np.array(rewards)` |
| $G_t = R_{t+1} + \gamma\, G_{t+1}$ | обратный цикл `for t in range(T - 1, -1, -1)` |
| $G_T = 0$ | `running = 0.0` перед циклом |
| $\gamma^{k}$ для всех $k$ | `gamma ** np.arange(T)` |
