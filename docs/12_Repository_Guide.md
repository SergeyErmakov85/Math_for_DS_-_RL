# Contributing to Ermakov Notes Framework

Спасибо за интерес к проекту. Этот документ описывает, как предлагать изменения так, чтобы они были приняты быстро.

Служебные документы репозитория ведутся на английском в части имён файлов и кода; текст правил и обсуждений — на русском. Русские термины при первом употреблении сопровождаются английским дублем в скобках.

---

## 1. Прежде чем начать

Прочитайте два документа — они экономят время на обеих сторонах:

- [`01_Style_Guide.md`](01_Style_Guide.md) — сводные правила с номерами вида `ENF-STYLE-001`.
- [`10_Review_Checklist.md`](10_Review_Checklist.md) — по этому чек-листу будет проверяться ваш вклад.

Правило с номером — это не рекомендация, а норма. Если вы считаете норму неверной, предложите изменить саму норму (см. раздел 6), а не обходите её в конкретном файле.

---

## 2. Настройка окружения

Обязательный минимум:

| Инструмент | Зачем | Проверка |
|------------|-------|----------|
| Git | версионирование | `git --version` |
| Node.js ≥ 18 | скрипты проверок | `node --version` |
| PowerShell 7+ | скрипты сборки | `pwsh --version` |

Дополнительно для полной сборки (только если правите пайплайн или примеры):

| Инструмент | Зачем |
|------------|-------|
| Pandoc ≥ 2.19 | конвертация во все форматы |
| TeX-дистрибутив с XeLaTeX (MiKTeX, TeX Live) | PDF |
| Obsidian | проверка хранилища и рендера MathJax |

Установка зависимостей «с нуля» подробно описана в [`11_Build_Pipeline.md`](11_Build_Pipeline.md).

---

## 3. Что и куда добавлять

| Вклад | Куда | Дополнительно |
|-------|------|---------------|
| Новое правило стиля | соответствующая глава `docs/style/` | добавить строку в сводный файл и пункт в `Review_Checklist.md` |
| Новый цветовой токен | `docs/02_Color_System.md` + `css/enf-tokens.css` | прогнать `node Scripts/check-contrast.mjs` |
| Новая SVG-иллюстрация | тематическая подпапка `svg/` | зарегистрировать в `svg/CATALOG.md` |
| Новый шаблон Mermaid | `mermaid/` | проверить рендер и в Obsidian, и в HTML-сборке |
| Новый промт | `docs/prompts/` | оформить по `Prompt_Standard.md`, приложить пример входа и выхода |
| Новый эталонный пример | `examples/` | обе версии: Learning Mode и Publication Mode |
| Исправление опечатки | там, где нашли | без церемоний, отдельным маленьким PR |

Новая дисциплина добавляется как набор цветовых токенов и шаблонов — **без изменения ядра фреймворка**. Если для вашей дисциплины приходится править ядро, это сигнал, что ядро спроектировано неверно: опишите ситуацию в issue.

## 4. Обязательные проверки перед отправкой

Запустите обе команды и приложите их вывод к описанию pull request:

```powershell
node Scripts/check-contrast.mjs          # палитра: контраст и дальтонизм
pwsh  Scripts/check.ps1 .                # ссылки, цвета, alt-текст, фронтматтер
```

Если вы меняли пайплайн или примеры, дополнительно соберите эталонный пример во все пять форматов:

```powershell
pwsh Scripts/build.ps1 -Source examples/Bellman_Equation.md -All
```

Pull request с падающими проверками не рассматривается — это экономит время ревьюера на вещах, которые машина находит сама.

---

## 5. Оформление pull request

1. Ветка от `main`, имя вида `style/contrast-fix`, `svg/markov-chain`, `docs/typography-ch3`.
2. Один pull request — одно изменение по смыслу. «Заодно поправил ещё десять файлов» усложняет ревью и откат.
3. В описании укажите: что изменилось, зачем, каких правил `ENF-*` касается, вывод проверок из раздела 4.
4. Изменения в уже принятые файлы описывайте явно построчно: путь → что изменилось → почему.
5. Коммиты — в стиле Conventional Commits: `feat(svg): добавлена диаграмма цепи Маркова`, `fix(build): исправлен перенос цвета формул в EPUB`.

---

## 6. Изменение правил

Правило `ENF-*` меняется только через issue с обоснованием. В issue должно быть:

- номер правила и его текущая формулировка;
- в чём проблема — с конкретным примером материала, где правило мешает;
- предлагаемая новая формулировка и пара примеров «плохо / хорошо»;
- оценка последствий: какие файлы репозитория перестанут соответствовать норме.

Принятое изменение фиксируется строкой в журнале решений `docs/reference/PROGRESS.md` и записью в `CHANGELOG.md`. Номер правила при изменении смысла **не переиспользуется**: старый номер помечается как устаревший, вводится новый. Ссылки в чужих материалах не должны молча менять значение.

---

## 7. Вклад, созданный ИИ-агентом

Материалы, сгенерированные ИИ, принимаются на общих основаниях при двух условиях:

- агент работал по [`../agents/CODEX.md`](../agents/CODEX.md) или [`../agents/CLAUDE.md`](../agents/CLAUDE.md);
- вы лично прочитали результат целиком и отвечаете за его корректность.

Отдельно проверьте то, в чём языковые модели ошибаются чаще всего: несуществующие ссылки и источники, выдуманные возможности плагинов, пропущенные шаги вывода, обозначения, использованные до определения.

---

## 8. Кодекс поведения

Обсуждаем работу, а не людей. Критика конкретна и относится к тексту или коду. Вопрос новичка — нормальная часть процесса; ответ «прочитай документацию» без ссылки на конкретный раздел таковой не является.

---

## Лицензия вклада

Отправляя pull request, вы соглашаетесь с распространением вашего вклада на условиях [MIT](../LICENSE).
