# CSS фреймворка

Во фреймворке четыре CSS-файла и ровно один из них содержит значения цветов. Остальные три берут их через `var()`. Это исполнение `ENF-COLOR-001`: HEX-код живёт в единственном месте, и правка палитры — правка одного файла.

## Где что лежит

| Файл | Кто читает | Содержит |
|------|------------|----------|
| [`css/enf-tokens.css`](../css/enf-tokens.css) | все остальные | значения цветов: светлая и тёмная темы, поверхности, пять ролевых тонов |
| [`css/enf-html.css`](../css/enf-html.css) | Pandoc — HTML, EPUB, Reveal.js | типографика и вёрстка собранных документов |
| [`snippets/enf-math.css`](../snippets/enf-math.css) | Obsidian | типографика текста и оформление формул в хранилище |
| [`snippets/enf-callouts.css`](../snippets/enf-callouts.css) | Obsidian | коллауты: определение, теорема, лемма, следствие, доказательство, пример, замечание, интуиция, предупреждение |
| [`snippets/enf-code.css`](../snippets/enf-code.css) | Obsidian | подсветка кода и блоки вывода: темы «Тетрадь» и «Доска» из [`13_Code_Module_Python.md`](13_Code_Module_Python.md) |
| [`css/lesson-export.css`](../css/lesson-export.css) | Pandoc — HTML | фон, рамки и блоки вывода кода в HTML-сборке |

Разделение проходит по потребителю, а не по содержимому. `css/` подключается Pandoc-сборкой и указан в [`Build/defaults/*.yaml`](../Build/defaults/); `snippets/` предназначен только для Obsidian и осмыслен исключительно внутри хранилища.

## Почему сниппеты лежат вне хранилища

Хранилище Obsidian — весь репозиторий, но Obsidian подключает сниппеты только из `.obsidian/snippets/`. Значит, физические копии сниппетов обязаны находиться там.

Держать там же и рабочие версии означало бы два источника истины: правка в одной копии молча расходится с другой, а токены к тому же нужны Pandoc-сборке. Поэтому источник лежит в `css/` и `snippets/`, а копии в `.obsidian/snippets/` **порождаются**:

```powershell
node Scripts/gen-obsidian-css.mjs
```

Скрипт переносит `css/enf-tokens.css`, `snippets/enf-math.css`, `snippets/enf-callouts.css` и `snippets/enf-code.css` в `.obsidian/snippets/`, снабжая каждый заголовком «порождённый файл». Правки, внесённые прямо в `.obsidian/snippets/`, теряются при следующей генерации — это не побочный эффект, а цель.

## Что происходит после правки токенов

`css/enf-tokens.css` — вершина цепочки. Из него порождаются четыре артефакта, и все они обязаны быть пересозданы одной командой:

```powershell
npm run gen
```

| Генератор | Что создаёт | Зачем отдельный формат |
|-----------|-------------|------------------------|
| `Scripts/gen-latex-colors.mjs` | `Build/templates/enf-colors.tex` | LaTeX не читает CSS |
| `Scripts/gen-mermaid-init.mjs` | `mermaid/init-config.md` и init-строки диаграмм | Mermaid не поддерживает внешние файлы тем: цвета обязаны быть в тексте диаграммы |
| `Scripts/gen-obsidian-css.mjs` | три сниппета внутри хранилища | Obsidian не видит файлы вне хранилища |

Помимо генерации палитру нужно перепроверить на доступность:

```powershell
node Scripts/check-contrast.mjs
```

Проверка считает контраст на светлом и тёмном фоне (порог WCAG AA) и различимость тонов при дейтеранопии и протанопии. Расхождение порождённых файлов с источником ловится в CI задачей `generated` — она перегенерирует всё и требует пустой `git diff`.

## Как цвет попадает в формулу

Ни в материале, ни в SVG, ни в диаграмме HEX-код не пишется. В формулах используются макросы ролей — `\enfVar`, `\enfFun`, `\enfPar`, `\enfOp`, `\enfTgt`. В Obsidian и HTML макрос вешает CSS-класс, а не фиксирует цвет: при переключении темы формула перекрашивается сама.

```latex
% плохо: значение по месту — не переносится в DOCX и ломает единый источник истины
\lim_{\textcolor{#2563EB}{x}\to a} \textcolor{#E67E22}{f}(x) = L

% хорошо
\lim_{\enfVar{x} \to \enfVar{a}} \enfFun{f}(\enfVar{x}) = \enfTgt{L}
```

В SVG допустимо единственное исключение: HEX как запасное значение внутри `var()` — `fill="var(--enf-color-variable, #2563EB)"`. Без него файл, открытый вне Obsidian и вне сборки, остался бы бесцветным. Проверка `Scripts/check-colors.mjs` знает про это исключение и на него не срабатывает.
