# Диаграммы

Иллюстрация в учебном тексте не украшает его, а сообщает то, что словами обошлось бы дороже. Из этого следует главный критерий: если рисунок можно убрать без потери смысла, его следует убрать.

Во фреймворке две технологии, и выбор между ними не вопрос вкуса.

| Задача | Технология |
|--------|------------|
| Геометрия: оси, графики, площади, векторы | SVG |
| Точное расположение элементов имеет значение | SVG |
| Структура: последовательность, ветвление, граф, состояния | Mermaid |
| Схема, которая будет часто меняться | Mermaid |

Mermaid раскладывает элементы сам, и повлиять на раскладку почти нельзя — для графика функции это неприемлемо, для блок-схемы алгоритма, наоборот, экономит время.

## 1. Общие правила

**`ENF-DIAG-010` · Только цвета палитры** — *Обязательно* 🤖

Цвета берутся из токенов. В SVG — через `var(--enf-color-*, #запасной)`, где запасное значение обеспечивает корректность файла вне Obsidian. В Mermaid — через порождаемый init-блок; правка цвета руками в отдельной диаграмме теряется при следующей генерации.

```xml
<!-- плохо -->
<circle fill="#3498db" />

<!-- хорошо -->
<circle fill="var(--enf-color-variable, #1D5B85)" />
```text
**`ENF-DIAG-011` · Не более четырёх тонов на диаграмму** — *Обязательно* 👁

Лимит тот же, что у Learning Mode для формул. Схема, где каждый элемент своего цвета, не читается: глазу не за что зацепиться.

**`ENF-DIAG-012` · Подписи — текстом** — *Обязательно* 🤖

Текст на диаграмме остаётся элементом `<text>` и никогда не переводится в кривые. Текст, ставший кривыми, не ищется, не копируется, не озвучивается программой чтения с экрана и не переводится на другой язык.

**`ENF-DIAG-013` · Целые координаты и сетка 20** — *Рекомендуется* 👁

Координаты — целые числа, узлы по возможности кратны 20. Дробные координаты появляются от редактирования мышью и делают файл неудобным для правки руками, а править эти файлы придётся.

**`ENF-DIAG-014` · Стандартные холсты** — *Обязательно* 🤖

| Формат | Размер | Когда |
|--------|--------|-------|
| Широкий | 800 × 500 | схемы общего вида |
| Квадратный | 500 × 500 | графики функций, координатные плоскости |
| Полоса | 800 × 300 | линейные последовательности, шкалы |
| Высокий | 500 × 700 | деревья, многослойные сети |

Единые размеры дают одинаковый кегль подписей во всех иллюстрациях книги. Разнобой холстов заметен читателю сразу, хотя он редко может объяснить, что именно его смущает.

**`ENF-DIAG-015` · Толщина линий не менее 1.5** — *Обязательно* 👁

Более тонкие линии пропадают при печати и на экранах с масштабированием.

**`ENF-DIAG-016` · Никаких градиентов, теней, фильтров и растровых вставок** — *Обязательно* 🤖

Они по-разному обрабатываются при экспорте в PDF, DOCX и EPUB и являются декоративными, то есть запрещены по `ENF-COLOR-040`.

## 2. Доступность диаграмм

**`ENF-DIAG-030` · Alt-текст описывает содержание** — *Обязательно* 🤖

Alt-текст сообщает, что изображено и что из этого следует, а не называет тип объекта.

```markdown
<!-- плохо -->
![схема](../SVG/rl/markov-chain-3-states.svg)
![график функции](../SVG/functions/tangent-derivative.svg)

<!-- хорошо -->
![Цепь Маркова из трёх состояний: из состояния A система с вероятностью 0,7
остаётся в A и с вероятностью 0,3 переходит в B; состояние C поглощающее](../SVG/rl/markov-chain-3-states.svg)
```
**`ENF-DIAG-031` · У каждого SVG есть `<title>` и `<desc>`** — *Обязательно* 🤖

```xml
<svg role="img" aria-labelledby="title desc" ...>
  <title id="title">Касательная как предел секущих</title>
  <desc id="desc">График функции с фиксированной точкой и серией секущих,
    проведённых через неё и приближающиеся точки. По мере сближения
    секущие стремятся к касательной, наклон которой равен производной.</desc>
```text
`<title>` короткий, `<desc>` содержательный. Они работают, даже когда файл открыт напрямую, вне материала.

**`ENF-DIAG-032` · Смысл дублируется нецветовым признаком** — *Обязательно* 👁

Различие, переданное цветом, дублируется формой узла, типом линии (сплошная, штриховая, пунктирная), штриховкой или подписью. Диаграмма обязана оставаться понятной в чёрно-белой печати.

**`ENF-DIAG-033` · Диаграмма читается в обеих темах** — *Обязательно* 👁

Проверяется открытием файла в браузере при светлой и тёмной теме системы. Частая ошибка — чёрная обводка, заданная явно: на тёмном фоне она исчезает. Обводка берётся из `--enf-color-neutral`, а не из литерала `black`.

## 3. Правила для SVG

**`ENF-DIAG-020` · Структура файла** — *Обязательно* 🤖

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 800 500"
     width="800" height="500" role="img" aria-labelledby="t d">
  <title id="t">…</title>
  <desc id="d">…</desc>
  <style>
    .axis  { stroke: var(--enf-color-neutral, #414A54); stroke-width: 1.5; }
    .curve { stroke: var(--enf-color-function, #8A5214); stroke-width: 2.5; fill: none; }
    .lbl   { font: 16px 'Inter', sans-serif; fill: var(--enf-color-neutral, #414A54); }
  </style>
  <!-- содержимое -->
</svg>
```
Цвета задаются классами в блоке `<style>`, а не атрибутами на элементах: так их видно все сразу и легко проверить на соответствие палитре.

**`ENF-DIAG-021` · Имя файла описывает содержание** — *Обязательно* 👁

`markov-chain-3-states.svg`, а не `diagram2.svg`. Имена в kebab-case, латиницей, по-английски.

**`ENF-DIAG-022` · Каждый файл зарегистрирован в каталоге** — *Обязательно* 🤖

Строка в [`../../SVG/CATALOG.md`](../../SVG/CATALOG.md) с путём, описанием и размером холста. Незарегистрированный файл через полгода будет нарисован заново, потому что о нём никто не вспомнит.

## 4. Правила для Mermaid

**`ENF-DIAG-040` · Разрешены только типы, поддержанные обеими средами** — *Обязательно* 🤖

Obsidian и Pandoc используют разные версии Mermaid.

Разрешено: `flowchart`, `graph`, `stateDiagram-v2`, `sequenceDiagram`, `classDiagram`, `pie`, `gitGraph`.

Запрещено: `mindmap`, `timeline`, `quadrantChart`, `sankey`, `xychart`, `block` — они либо отсутствуют в одной из версий, либо помечены авторами Mermaid как экспериментальные, а экспериментальный синтаксис меняется между версиями без предупреждения.

**`ENF-DIAG-041` · Init-блок порождается, а не пишется** — *Обязательно* 🤖

```powershell
node Scripts/gen-mermaid-init.mjs
```text
Скрипт читает `Build/css/enf-tokens.css` и переписывает init-блоки во всех шаблонах `Mermaid/`. Причина такого устройства: Mermaid не умеет подключать внешние темы, цвета обязаны быть в тексте диаграммы, и единственный способ сохранить единый источник истины — порождать их.

**`ENF-DIAG-042` · Направление потока сверху вниз или слева направо** — *Рекомендуется* 👁

`flowchart TD` для алгоритмов и деревьев, `flowchart LR` для конвейеров и последовательностей. Направления `BT` и `RL` противоречат привычке чтения и замедляют восприятие без выигрыша.

**`ENF-DIAG-043` · Подписи на рёбрах при ветвлении** — *Обязательно* 👁

Каждое ребро, выходящее из ромба условия, подписано условием, при котором оно выбирается. Ветвление без подписей заставляет читателя угадывать, какая ветвь «да».

```
%% плохо
A{Сошлось?} --> B[Конец]
A --> C[Ещё шаг]

%% хорошо
A{Сошлось?} -->|да| B[Конец]
A -->|нет| C[Ещё шаг]
```text
**`ENF-DIAG-044` · Не более пятнадцати узлов** — *Рекомендуется* 👁

Диаграмма крупнее не помещается в полосу PDF читаемым кеглем. Большую схему делят на уровни: обзорная диаграмма и детализация отдельных блоков.

## 5. Проверка

```powershell
node Scripts/check-colors.mjs SVG/ Mermaid/   # цвета вне палитры
node Scripts/check-alt.mjs .                  # alt-текст, title, desc
pwsh  Scripts/check.ps1 .                     # запрещённые типы диаграмм
```
Ручная проверка, которую не заменяет скрипт: открыть диаграмму в светлой и тёмной теме и посмотреть на неё в чёрно-белом виде.
