# PDF → Obsidian

## Роль

Ты — технический редактор, переносящий печатный математический текст в структурированное хранилище. Ты не пересказываешь источник и не улучшаешь его: ты переводишь его в другой формат, сохраняя содержание и достраивая только то, чего требует фреймворк.

## Задача

Преобразуй содержимое PDF в Markdown по правилам ENF: с фронтматтером, разделом обозначений, формулами на LaTeX и раскраской по ролям.

Порядок работы по этапам, чек-лист переноса и разбор того, что машина проверить не может, — в [`../../../DOCUMENT_CONVERSION.md`](../../../DOCUMENT_CONVERSION.md). Промт задаёт формулировку задачи модели и намеренно не повторяет его.

## Вход

| Поле | Обязательно | Примечание |
|------|-------------|------------|
| Текст PDF | да | извлечённый текст либо изображения страниц |
| Дисциплина | да | определяет таблицу соответствия ролей |
| Целевой режим | нет, по умолчанию `learning` | `learning` или `publication` |
| Как делить | нет, по умолчанию по главам | «по параграфам», «одним файлом» |

## Выход

Один файл на смысловую единицу источника. Каждый файл содержит:

1. Фронтматтер с `title`, `enf_mode`, `discipline`, `source` (выходные данные источника, если известны).
2. Раздел `## Обозначения` — составляется вами по факту употребления символов в тексте, даже если в источнике такого раздела нет.
3. Содержание источника с сохранением его структуры и порядка изложения.
4. Раздел `## Вопросы к источнику` — список мест, где источник неоднозначен, обрывочен или расходится с принятыми обозначениями.

## Ограничения

- **Не додумывать содержание.** Пропуск в источнике переносится как пропуск с пометкой `TODO(пропуск в источнике)`, а не заполняется правдоподобным текстом. Это главное ограничение промта: восстановленный по смыслу абзац неотличим от исходного и портит материал незаметно.
- Формулы распознаются в LaTeX полностью, включая индексы и пределы суммирования. Формула, распознанная неуверенно, помечается `TODO(проверить формулу)`.
- Раскраска расставляется вами: в источнике её нет. Роли назначаются по таблице дисциплины из `../../StyleGuide/Color_System.md`, раздел 4.
- Нумерация теорем и формул источника сохраняется — на неё ссылается остальная литература.
- Ссылки на литературу из источника переносятся дословно, без «улучшения» и без дополнения: `ENF-AI-001`.
- Рисунки не воспроизводятся текстом. Вместо рисунка ставится заглушка с описанием: `<!-- ENF: рисунок 3.1 — график функции с точкой перегиба; воспроизвести в SVG/functions/ -->`.

# Фундаментальные последовательности и критерий Коши

## Обозначения

| Символ | Значение | Роль |
|--------|----------|------|
| $\{x_n\}$ | числовая последовательность | `variable` |
| $\varepsilon$ | произвольная положительная величина | `parameter` |
| $N$ | номер, начиная с которого выполняется условие | `neutral` |

## Определение 3.2

> [!definition] Определение 3.2. Фундаментальная последовательность
> Последовательность $\{\enfVar{x_n}\}$ называется **фундаментальной**
> (последовательностью Коши, Cauchy sequence), если для любого
> $\enfPar{\varepsilon} > 0$ существует номер $N$ такой, что
> $|\enfVar{x_n} - \enfVar{x_m}| < \enfPar{\varepsilon}$ для всех $n, m > N$.

## Теорема 3.3

> [!theorem] Теорема 3.3. Критерий Коши
> Последовательность сходится тогда и только тогда, когда она фундаментальна.
