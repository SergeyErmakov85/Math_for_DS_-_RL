## 4. Зафиксированные допущения (ASSUMPTION)

Действуют, пока заказчик не ответит на вопросы раздела 5. Каждое допущение снимается или подтверждается по итогам Фазы 0.

- **ASSUMPTION-01 — Язык.** Контент материалов — русский; имена файлов, код, служебные документы репозитория (`README`, `LICENSE`, `CHANGELOG`, `CONTRIBUTING`) — английский. Русские термины при первом употреблении сопровождаются английским дублем в скобках.
- **ASSUMPTION-02 — Лицензия.** MIT, правообладатель — Sergey Ermakov, год 2026. Единая лицензия на код и на содержимое.
- **ASSUMPTION-03 — Предыдущие версии.** Style Guide v1–v3 и готовой палитры HEX в наличии нет; сводный документ версии v4 создаётся с нуля. Имя `..._v4.md` из архитектуры сохраняем как заданное, несмотря на отсутствие предшественников.
- **ASSUMPTION-04 — Размещение фреймворка.** ENF разворачивается в корне текущего репозитория `Math_for_DS_-_RL`, а не в отдельном репозитории `Ermakov-Notes`. Существующий двухстрочный `README.md` в Фазе 1 будет **заменён** на README фреймворка (старый текст переносится в раздел «О репозитории»).
- **ASSUMPTION-05 — Приоритет компонент.** Порядок реализации — как в `<workflow>`: D4/D1-ядро → D3 → D2 → D5/D6 → D7/D8 → D10.
- **ASSUMPTION-06 — Сборка без Make.** Точка входа сборки — `Scripts/build.ps1` плюс тонкая обёртка `package.json` (`npm run build:all`). `Makefile` добавляется опционально для Linux/macOS-контрибьюторов, но не является обязательным путём.
- **ASSUMPTION-07 — Формулы в Obsidian.** Рендер MathJax; раскраска формул строится на `\textcolor{...}{...}` с макросами, определяемыми один раз, — приём, работающий и в MathJax, и в LaTeX-сборке. `\color` в групповой форме не используется как ненадёжный.
- **ASSUMPTION-08 — Целевая ОС разработки.** Windows 11 + PowerShell 7. Скрипты пишутся кроссплатформенно, но проверяются на Windows.
- **ASSUMPTION-09 — Плагины Obsidian.** Vault рассчитан на Templater, Dataview и Tasks — все три бесплатные и общедоступные. Vault обязан открываться и без них (базовая структура не ломается), с деградацией функциональности.
- **ASSUMPTION-10 — Режим по умолчанию.** Во фронтматтере шаблонов `enf_mode: learning` для лекций и задачников, `enf_mode: publication` для глав книг, статей и презентаций.

## 6. Журнал решений (ADR)

Формат: одна строка на решение — дата, решение, причина.

- 2026-07-31 — Скрипты качества и сборки пишем на Node.js + PowerShell вместо Python — Python в целевой системе фактически отсутствует, а Node.js v24 есть.
- 2026-07-31 — PDF собираем через XeLaTeX, а не pdfLaTeX — кириллица в контенте требует Unicode-движка.
- 2026-07-31 — Роль `make all` выполняет `Scripts/build.ps1` + npm-скрипт — GNU Make в системе нет, навязывать его установку противоречит требованию «стек без барьеров».
- 2026-07-31 — Фреймворк разворачивается в существующем репозитории, прежний `README.md` заменён — решение заказчика (Q4); прежний текст сохранён в разделе «О репозитории».
- 2026-07-31 — Номера правил `ENF-*` неизменяемы: при смене смысла старый номер помечается `DEPRECATED`, вводится новый — иначе ссылки в уже написанных материалах молча меняют значение.
- 2026-07-31 — Раскраска в исходнике пишется именем токена (`\textcolor{enfVariable}{x}`), а не HEX — HEX невозможно корректно перенести в DOCX и EPUB, а также ломает единый источник истины.
- 2026-07-31 — Разрешены только те типы диаграмм Mermaid, что поддержаны и Obsidian, и Pandoc — требование двойной совместимости из `<design_principles>`.
- 2026-07-31 — Примеры в `examples/` считаются тестами фреймворка: правило, не ломающее ни один пример при изменении, считается ничего не нормирующим.
- 2026-07-31 — **Палитра состоит из пяти семантических тонов, а не из восьми** — измерено численно: при обязательном контрасте 4.5:1 дихроматия оставляет место ровно для пяти ролей (минимум ΔE₀₀ ≈ 10,7), на шести минимум падает до 2–5, то есть до неразличимости. Проверка воспроизводится: `node Scripts/check-contrast.mjs`.
- 2026-07-31 — Индексы и счётчики ($i$, $n$, $t$) не получают собственного тона — подстрочное положение уже отличает их, а тон в палитре дефицитен.
- 2026-07-31 — Множества не получают собственного тона — начертание `\mathcal` уже выполняет эту работу и заодно исполняет требование дублирования цвета нецветовым признаком.
- 2026-07-31 — Введены два уровня требований к различимости: ядро из пяти тонов (порог ΔE₀₀ 9, обязателен дублирующий признак) и безопасная тройка `variable`/`function`/`parameter` (порог 12, разрешена в Publication Mode без оговорок).
- 2026-07-31 — Цвета подобраны численным поиском в CIE Lab с ограничениями по контрасту и тоновым окнам ролей, а не на глаз — иначе заявленные свойства доступности недоказуемы.
- 2026-07-31 — **Шрифты для PDF не задаются в конфигурации, а подбираются сборкой из списка кандидатов** — `fontspec` не подставляет замену, и названная, но не установленная гарнитура останавливает сборку. Проверено на месте: заявленные Charter, Inter и JetBrains Mono в целевой системе отсутствуют, PDF не собирался.
- 2026-07-31 — Все кандидаты в шрифты обязаны покрывать кириллицу — гарнитура без неё даёт пустые прямоугольники вместо текста, а это хуже несобравшегося PDF: такую ошибку легко не заметить.
- 2026-07-31 — **SVG в PDF: при отсутствии конвертера иллюстрация заменяется рамкой с alt-текстом**, а не роняет сборку. Реализовано фильтром `Build/filters/enf-svg.lua`; векторные копии создаёт `Scripts/convert-svg.ps1` при наличии rsvg-convert или Inkscape. Деградация намеренно заметная: печатается предупреждение с именем файла.
- 2026-07-31 — **Все проверки читают файлы через `readText()` с нормализацией переводов строк** — в рабочем каталоге на Windows они смешанные, а точка в регулярных выражениях JavaScript не совпадает с `\r`. Симптом обманчив: поле фронтматтера или ограждение блока кода просто «исчезает», и ошибка выглядит как отсутствующее поле.
- 2026-07-31 — Разбор ограждённых блоков кода реализован конечным автоматом, а не регулярным выражением — во фреймворке повсеместны вложенные ограждения (блок ` ```` ` с показанным внутри ` ``` `), на которых регулярное выражение закрывает внешний блок на первом внутреннем.
- 2026-07-31 — Маскирование блоков кода работает по кодовым единицам UTF-16, а не по кодовым точкам — эмодзи в пометках сложности задач сдвигали индексы и ломали проверку заголовков.
- 2026-07-31 — Документы с `discipline: meta` освобождены от лимитов режима раскраски — справка по палитре обязана показать все пять тонов сразу, и лимит для неё бессмысленен.
- 2026-07-31 — Нейтральный макрос `\enfNeu` не расходует лимит тонов — нейтральный тон не участвует в семантике.
- 2026-07-31 — **Конфликт с появившимися в корне `agents/AGENTS.md` и `agents/DOCUMENT_CONVERSION.md` решён приведением их к стандарту, а не отменой стандарта** — предложенная в них палитра из шести цветов с прямыми `\textcolor{#HEX}` нарушала три правила сразу и, что важнее, была измеримо хуже: шесть тонов дают неразличимые пары при дихроматии. Содержание файлов сохранено полностью, переписаны только цветовая часть и способ записи.
- 2026-07-31 — Роли `Reference points` и `ε`/`δ` из прежней палитры не получили отдельных тонов: точка, к которой стремится аргумент, играет ту же роль объекта рассмотрения, что и сам аргумент, а $\varepsilon$ и $\delta$ — оба настраиваемые величины. Различаются они обозначением, а не цветом, что и требуется правилом `ENF-COLOR-003`.
- 2026-07-31 — `agents/AGENTS.md` оставлен в корне как точка входа для агентов по общепринятому соглашению, но сведён к краткой сводке со ссылкой на полную конституцию `agents/CODEX.md` — дублировать её в двух местах значило бы завести второй источник истины.
- 2026-07-31 — `agents/DOCUMENT_CONVERSION.md` описывает порядок работы человека, промт `PDF_to_Obsidian.md` — постановку задачи модели; они ссылаются друг на друга и не пересекаются по содержанию.
- 2026-08-03 — **Макросы ролей вешают класс через `\class{}{}`, а не через `\htmlClass{}{}`** — `\htmlClass` принадлежит KaTeX; в MathJax его нет, расширение `html` определяет `\href`, `\class`, `\cssId`, `\style`, `\data`. Пока в преамбуле стояло `\htmlClass`, формула отрисовывалась сообщением «Undefined control sequence», то есть раскраска в Obsidian и в HTML/EPUB/Reveal.js не работала вовсе — при том, что CSS-классы, сниппеты и палитра были верны. Исправлено в `Obsidian/Vault/preamble.sty`, `Obsidian/Vault/_meta/mathjax-preamble.md` и `Build/templates/mathjax-macros.html`. Путь PDF/LaTeX не затронут: там макросы идут из `Build/templates/enf-colors.tex` и с MathJax не пересекаются. Имена классов, палитра и правила `ENF-*` не менялись. Проверено прогоном преамбулы и проверочной формулы через MathJax 3.2.1 (та же ветка, что бандлит Obsidian): все пять классов ролей появляются в разметке. Урок в пользу `ENF-AI-002`: ошибка держалась потому, что имя макроса выглядело правдоподобно и никем не проверялось на исполнении.
- 2026-08-03 — **Преамбула MathJax в хранилище загружается плагином Extended MathJax (`obsidian-latex`, 0.4.1) из `preamble.sty` в корне хранилища**, а не открытием заметки вручную. Плагин, его `manifest.json` и `community-plugins.json` лежат внутри `Vault/.obsidian/` и переносятся вместе с папкой, поэтому скопированное на другую машину хранилище показывает цветные формулы сразу. Отвергнутые варианты: (1) *закреплённая вкладка с преамбулой* — с Obsidian 1.7 фоновые вкладки загружаются отложенно, поэтому закрепление не гарантирует, что макросы зарегистрируются раньше открытия материала; (2) *`\newcommand` в каждом материале* — прямо запрещено `ENF-MATH-003` и задачу всё равно не решает: сценарий «перенесли один файл» без сниппетов из `.obsidian/snippets/` даёт классы без цвета. Заметка `_meta/mathjax-preamble.md` сохранена как запасной путь при выключенных плагинах и как проверочный стенд; при правке макросов меняются оба файла. Факты о плагине (`id`, путь преамбулы) взяты из `manifest.json` и кода релиза, а не из памяти (`ENF-AI-002`): в коде путь задан как `DEFAULT_SETTINGS.preamblePath` и настраивается через `data.json`, хотя README плагина называет его жёстко фиксированным.
- 2026-07-31 — Первый же написанный эталонный пример нарушил `ENF-MATH-021`: в уравнении Беллмана естественно возникает пять ролей при лимите четыре. Правило оставлено без изменений, пример переписан — это и есть тот случай, ради которого лимит вводился.
- 2026-09-17 — **Введено `ENF-MATH-025` «Сквозная раскраска в Learning Mode» и таблица «формула → код» (п. 5.6 модуля «Код»)** — пробный урок `materials/RL/Q_Learning_Frozen_Lake.learning.md` прошёл все машинные проверки, но оказался заметно беднее прежних материалов: 35 макросов на весь урок против 241 в `Lebesgue_Integral`. Цвет стоял только при первом появлении символа, а награда, состояние и индикатор терминальности оставались нейтральными даже в формулах, где лимит тонов был свободен. В коде не было ни разбора по маркерам, ни трассировки. Причины: `ENF-MATH-020` («запрет тотальной раскраски») без обратного правила читался как разрешение красить минимум; эталон модуля (приложение А) был прямо «без цветовой разметки»; единственная таблица моста была словарём имён, а не переводом формулы по частям. Решение: новое правило (старые номера не менялись); предупреждение `ENF-MATH-025` в `check-colors.mjs` о нейтральном символе, которому документ назначил роль, при свободном лимите тонов; раскрашенный эталон с таблицами «формула → код». Сделано предупреждением, а не ошибкой, пока не переработаны уже написанные материалы: в них оно срабатывает от 3 до 47 раз.

**Известные ограничения версии 1.0.0**

Это не дефекты, а следствия внешних ограничений; каждое задокументировано там, где с ним столкнутся.

1. **SVG в PDF без конвертера.** При отсутствии `rsvg-convert` или Inkscape иллюстрация в PDF заменяется рамкой с alt-текстом. Остальные четыре формата не затронуты. Лечится запуском `Scripts/convert-svg.ps1`.
2. **Цвет формул в DOCX.** Снимается фильтром: OMML не поддерживает цвет внутри формул. Именно поэтому `ENF-COLOR-003` требует дублировать смысл цвета словами.
3. **Макросы MathJax в Obsidian.** ~~У Obsidian нет настройки постоянной преамбулы: заметку `_meta/mathjax-preamble.md` нужно открыть один раз за сессию.~~ **Снято 2026-08-03:** преамбулу загружает плагин Extended MathJax из `preamble.sty`, оба файла идут в поставке хранилища. Ограничение возвращается, только если пользователь оставит плагины сообщества выключенными — тогда работает прежний запасной путь. При сборке через Pandoc ограничения нет.
