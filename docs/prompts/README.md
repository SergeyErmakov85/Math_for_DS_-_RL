# Prompts — библиотека промтов

Промты оформлены по единому стандарту [`../09_Prompt_Library.md`](../09_Prompt_Library.md): роль, задача, вход, выход, ограничения, пример, проверка. Каждый протестирован на минимальном примере — результат теста записан в конце промта.

| ID | Промт | Что делает |
|----|-------|------------|
| `ENF-PROMPT-001` | [`PDF_to_Obsidian.md`](PDF_to_Obsidian.md) | Переносит печатный источник в Markdown, не додумывая пропуски |
| `ENF-PROMPT-002` | [`Lecture_Generator.md`](Lecture_Generator.md) | Пишет лекцию с нуля в Learning Mode |
| `ENF-PROMPT-003` | [`Exercise_Generator.md`](Exercise_Generator.md) | Составляет задачник с решениями и разбором типичных ошибок |
| `ENF-PROMPT-004` | [`SVG_Generator.md`](SVG_Generator.md) | Рисует иллюстрацию в стиле библиотеки `svg/` |
| `ENF-PROMPT-005` | [`Research_Assistant.md`](Research_Assistant.md) | Разбирает статью: конспект, критика или вопросы к авторам |
| `ENF-PROMPT-006` | [`Book_Generator.md`](Book_Generator.md) | Пишет главу книги в Publication Mode |

## Как пользоваться

Промт подаётся модели вместе с [`../../agents/CODEX.md`](../../agents/CODEX.md) — он содержит только специфику своей задачи и опирается на конституцию в общем. Промт, поданный без конституции, даст материал, не проходящий проверки: общие правила в нём намеренно не продублированы.

## Как добавить свой

1. Взять структуру из [`../09_Prompt_Library.md`](../09_Prompt_Library.md), заполнить все семь разделов.
2. Присвоить следующий свободный `ENF-PROMPT-XXX`. Номера не переиспользуются.
3. Прогнать на минимальном примере, результат прогнать через `pwsh Scripts/check.ps1`.
4. Записать итог теста в раздел «Проверка» промта.
5. Добавить строку в таблицу выше и в `../Prompt_Standard.md`, раздел 4.

Непроверенный промт в библиотеку не добавляется: он опаснее отсутствующего, потому что выглядит готовым инструментом.
